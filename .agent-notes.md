## Design decisions (2026-10-10)
- Strict parsers are NOT modified. Lenient functions are separate, beside them,
  with theorems: strict = .ok d -> lenient = (d, []).
- Diagnostic: class (inductive DiagnosticClass, classified from the ParseError
  message), message, offset (scalar values, 0-based), line (1-based, LF only,
  same convention as Wasm/Ops/Parse.lean lineColumnOfOffset and F*
  position_of_offset), column (1-based, scalar values).
- N-Triples/N-Quads: one generic lenient line fold (reader parameter), sync =
  skipToEol from statement start then skipEol. Line tracking O(1) per EOL.
- Turtle: lenient statement loop mirrors parseStatements; on error, fresh
  StatementScan from the statement start, resume at first cut position >= error
  offset. Same loop used per candidate by the streaming chunk fold.
- TriG: recovery inside graph blocks too (sync also at '}' in normal mode).
- maxErrors: Option Nat; on error number m+1 emit class tooManyErrors and stop.
