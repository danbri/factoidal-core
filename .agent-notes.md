### F2. F* W3C runner: SELECT row comparison accepts extra bindings

`binding_row_matches_with` (bin/w3c-runner/w3c_runner.ml line 906) checks
that each binding of the expected row is in the actual row, not the reverse.
An actual row that binds a variable the expected row leaves unbound matches.
Effect: the 12 tests of F1 score PASS (cast 3, functions 9). Equal solution
mappings have equal domains (SPARQL 1.1 §18.1.8); the Lean comparator
(formal/lean4/Harness/Compare.lean `rowMatch`, `domainsEqual`) checks this.
Recorded first on 2026-08-22 (docs/designissues/2026-08-22-lean4-w3c-harness.md,
finding 4). Fix: require equal domains; expect the F* sparql11 score to drop
by 12 until F1 is fixed.

### F4. F* command line parses the query with no base IRI

bin/factoidal-cli/factoidal_cli.ml calls `SPARQL11_Parser.parse_sparql
query_text` (no base); the F* W3C runner calls `parse_sparql_with_base` with
the query file's IRI. `-b` sets the data base only. A relative IRI in the
query is a parse error: bindings "VALUES inside GRAPH binding the same
variable as the graph name" (`<data01.ttl>`), construct/constructwhere04
(`FROM <data.ttl>`), exists "Exists within graph pattern"
(`graph <exists02.ttl>`), property-path pp34 (`GRAPH <ng-01.ttl>`), pp35
(`FILTER (?g = <ng-01.ttl>)`). Spec: SPARQL 1.1 §4.1.1.2 Relative IRIs,
RFC 3986 §5.1.3 (base from the retrieval URI). Fix: parse `--query FILE`
with the file IRI as base; add a query-base option for `-e`.

### F5. F* CONSTRUCT: template blank nodes from collection syntax get labels with ':'

The F* parser's `fresh_bnode_id` (SPARQL11.Parser.fst) makes the id

after the prefix. The F* runner compares graphs in memory and passes. Lean
names the same node without ':'.
