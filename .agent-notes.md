## Findings (2026-10-10)
- `Wasm/Ops/Query.lean` `queryParsedDatasetWith` builds `EvalEnv` with no `now`: NOW() is an error.
- Callers of `queryParsedDatasetWith`: Query.lean (queryParsedDataset, queryDatasetIO, queryDataset12IO),
  Handles.lean (datasetQuery, datasetQuery12), Store.lean, StoreHandles.lean, QueryHdt.lean, Block.lean,
  Harness/QueryPhases.lean. CLI uses pure `queryDatasetOf` / `updateDatasetOf` (Wasm/Cli.lean queryCmd/updateCmd).
- `Std.Time.Timestamp.now` (@[extern "lean_get_current_time"]) is the toolchain clock (Lean 4.33.1).
  Wasm/build-wasm.sh does NOT regenerate Std.Time C (libuv refs), so importing Std.Time into the library
  would break the wasm link. Needs a decision (see Next step).
- Existing: `Fn.DateTime.civilFromDays`, `XSD.canonicalDateTime`.

## Decisions
- Clock: `Std.Time.Timestamp.now` (lean_get_current_time, in the Lean runtime io.cpp, which the wasm
  build already compiles). Imported narrowly (`Std.Time.DateTime.Timestamp`, closure = 26 Std.Time
  modules, no libuv). build-wasm.sh must generate C for those 26 modules (STD_DIRS lacks Std/Time).
- Pure formatter `L4Factoidal/SPARQL/Now.lean` `dateTimeOfUnixMillis` (uses Fn.DateTime.civilFromDays +
  XSD.canonicalDateTime); #guards: epoch, leap 2000/2024, 2^31 s, 2100 non-leap, 2^32 s, ms fraction, pre-epoch.
- IO read: `Wasm/Ops/Clock.lean` `nowDateTime` (once per execution).
