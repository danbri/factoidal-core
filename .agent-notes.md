## Findings (2026-10-10)

- No Lean HTTP/1.1 request-message parser exists (HTTP/Server.lean has only the
  Request record, routing and negotiation; HTTP/Client.lean parses responses).
- `ProtocolService.serve` and `GraphStoreService.serve` work over an in-memory
  Dataset / GraphStore. No backend; reference evaluator.
- Persisted update path today: `l4block-delta-log` (Harness/DeltaLogTool) =
  parse -> `deltaBatchForUpdate?` (DATA forms + CLEAR/DROP/CREATE only, no WHERE)
  -> DLB1 frame -> append-at-size + fsync. Native readers replay the DEFAULT
  graph only (`foldDeltaBatches .. none`), compaction is default-graph only
  (`...-compacted-default-dlog-v1`). IBK4/IBK5 quad generations: no DLOG at all.
- npm `factoidal update` / `compact` print "not yet wired" (exit 3).
- W3C protocol tests: all 7 update tests write NAMED graphs; GSP tests write
  named graphs. So named-graph deltas are needed for a useful score.

## Design

- Lean library: `L4Factoidal/HTTP/Wire.lean` (HTTP/1.1 request framing from
  bytes, response bytes), `L4Factoidal/SPARQL/StoreEndpoint.lean` (routing,
  protocol query/update, GSP, service description, negotiation, delta diff and
  replay with write scope).
- Write scope: IBK3 -> default graph only (what native replay/compaction read);
  IBK4/IBK5 -> all graphs, server-only (native quad tools ignore DLOG: issue +
  xfail).
- Update = reference `applyUpdateIn` over the served view, persisted as the
  diff (DeltaEntry list) in one DLB1 batch; two-phase: op returns append bytes,
  host appends at expected size + fsync, `storeServeCommit` folds + answers.
- Wasm ops (Wasm/Ops/StoreServe.lean): storeServeKeys, storeServeOpen,
  storeServeRequest (blob in = request bytes, blob out = response or append
  bytes), storeServeCommit, storeServeClose.
- Host: npm/factoidal/bin/serve.mjs (+ worker with raised stack), `serve`
  command.
