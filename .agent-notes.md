## Findings (cause of each quadratic)
- Flatten.lean keeps NmNode/NmGraph/NmState.graphs/idmap as association lists: O(n) per lookup/update.
- nodeAppendProp dedup (flArrContains) calls expandedEqual (two JCS serialisations) against EVERY
  item already in the property array: O(n) serialisations per append, O(n^2) per fan-out node. This is the
  dominant cost in the task's measurement (fanout shape: node map 3.9 s of 4.7 s at n=1600).
- items ++ [v] list append per value; flInsertByKey/flSortByKey insertion sort with strLt that
  converts both strings to List Char at every comparison.
- Frame: FState.embeds/bnodes association lists, arena addOutput `xs ++ [item]`.
- Expand.sortMapEntries is an insertion sort (wide / expand quadratic). Outside the node map; see report.
