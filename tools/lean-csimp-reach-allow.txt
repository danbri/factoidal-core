# Findings of `tools/lean-csimp-reach.py --gate` that were read and left on purpose.
# https://github.com/danbri/factoidal/issues/871
#
# One line per finding:    <left side of the @[csimp] theorem> <owner>   # reason
# A finding is a C function (the owner) that still reaches the left side after the
# replacement. The reason is required: the gate fails on a line without one. `*` in a
# name matches any text. A line that matches no finding is reported as stale; remove it.
# Removing a line because the finding was repaired is the goal, as in
# tools/lean-tail-recursion-allow.txt.
#
# A finding that is held by a specification (the left side of another theorem) that no
# live code reaches needs no line: the tool suppresses it. A specification is live when a
# finding against it, held by live code, is not on this list. So the lines below name the
# call that first reaches each specification, and not each call inside it.
#
# Reasons used (read on 2026-10-15; each names the file where it can be checked):
#   leaf      the fast form (a loop) calls the specification for an input where the
#             specification does not recurse, as its comment says
#   bound     the call is in a branch for a size that no array reaches (2^64 characters)
#   twin      the fast form handles the shapes it improves and calls the specification,
#             whose parts are fast forms, for the others
#   guard     a private definition that only the `#guard` lines of the same module call;
#             its C function is emitted and nothing runs it
#   spec      a specification whose callers are `#guard` lines and theorem statements
#   dead arm  a step function whose arm that names the specification is not taken by the loop
#   fixture   a known-bad example kept on purpose
