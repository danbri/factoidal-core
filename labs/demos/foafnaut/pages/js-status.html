Status on 8 November 2026. Every number here comes from the repository's own test runners.

Page scripts today

Two engines run a page's scripts, and Settings chooses between them (Page scripts: BubblePopJS, QuickJS-NG, None). Both run the same page objects on Lean's DOM: Lean's event loop decides every callback, and every change to the page is a typed command on Lean's DOM.

  • BubblePopJS, the JavaScript engine written in Lean, compiled with the rest of the engine. The default in the app and on the Hub.
  • QuickJS-NG, compiled to WebAssembly and run by WasmVM, the WebAssembly engine written in Lean. A choice in Settings.

Speed on the Hub

On the Hub the engine is itself WebAssembly, so the guest ran in an interpreter inside WebAssembly. WasmVM now checks the guest and translates it into a module the browser's own WebAssembly engine runs. Lean still decides every step and every DOM change.

WebAssembly in pages

Page scripts have the WebAssembly JavaScript API on both engines: WebAssembly.validate, compile, instantiate, Module, Instance, Memory (with buffer and grow), Table, Global, Tag, Exception and the three error types. Lean decodes, validates and runs each module in WasmVM, in a store of the page's own. The browser's own WebAssembly engine runs none of them.

What pages can use

Timers, animation frames, microtasks and Promises; clicks and pointer events with coordinates; taps on SVG shapes; createElement and createElementNS; selectors matched by Lean; DOMParser; MutationObserver; forms, checkboxes and radio buttons; layout reads such as clientWidth and getBoundingClientRect; WebGPU and WebGL drawing, each command checked by Lean; Canvas 2D (paths, gradients, patterns, text, images, getImageData), drawn by Lean.

Computed by Lean, one call for each operation: TextDecoder and TextEncoder (every encoding of the Encoding Standard, with fatal, ignoreBOM and streaming); URL and URLSearchParams (the WHATWG URL parser, every setter); atob and btoa; crypto.getRandomValues and crypto.randomUUID (a Lean generator seeded by the host); crypto.subtle with digest (SHA-1, SHA-256, SHA-384, SHA-512), HMAC, HKDF, PBKDF2, ECDSA and ECDH on P-256, Ed25519, X25519 and ChaCha20-Poly1305: Lean holds the WebCrypto rules and HACL* computes the primitives, each promise settled by a task. Also structuredClone, and performance.mark and performance.measure.

Shadow DOM and frames, decided by the built-in engine (the demo): attachShadow, shadowRoot, slots (named, default and manual) with assignedNodes, assignedElements and slotchange; declarative shadow roots in the HTML parser; events through shadow trees, retargeted, with composedPath; :host, :host() and ::slotted() rules, and layout on the flat tree. An iframe has a document of its own (about:blank, srcdoc, or a URL the host loads), with contentDocument, contentWindow and its functions for a frame of the same origin. The sandbox attribute is decided by the built-in engine: a frame without allow-same-origin has an opaque origin, without allow-scripts runs no script, and with allow-scripts but not allow-same-origin runs in a session of its own that talks to the page only by postMessage. Also window.postMessage and MessageChannel.

Web platform tests, subtests passed before and after (BubblePopJS / QuickJS-NG, desktop engine, 9 November): shadow-dom 25 to 641 / 752 of Chrome's 14,706; webmessaging 13 to 92 / 102 of 298; the-iframe-element 9 to 27 of 233; the-window-object 107 / 110 to 128 / 151 of 1,000. With frame documents, pages that test through an iframe run: a sample of 175 Test262 pages 0 to 97 / 145, 78 legacy multi-byte decoding pages 0 to 45,384 / 15,660 subtests (with Lean's decoders), 18 quirks pages 3 to 58 on QuickJS-NG.

Not yet: drawing an iframe's document; module scripts and fetch from scripts, so the ObservableHQ notebooks the rest of the Hub uses do not run here; the innerHTML setter; Range and TreeWalker; lone surrogates in strings; AES, RSA, P-384, P-521, Ed448 and X448 in crypto.subtle (HACL* has no such primitive, so each is refused with NotSupportedError; RSA for imported keys is future work); TextDecoderStream (no streams yet).
