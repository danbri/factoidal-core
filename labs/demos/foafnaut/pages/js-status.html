Status on 8 November 2026. Every number here comes from the repository's own test runners.

Page scripts today

Two engines run a page's scripts, and Settings chooses between them (Page scripts: BubblePopJS, QuickJS-NG, None). Both run the same page objects on Lean's DOM: Lean's event loop decides every callback, and every change to the page is a typed command on Lean's DOM.

  • BubblePopJS, the JavaScript engine written in Lean, compiled with the rest of the engine. The default in the desktop browser.
  • QuickJS-NG, compiled to WebAssembly and run by WasmVM, the WebAssembly engine written in Lean. The default on the Hub.

Speed on the Hub

On the Hub the engine is itself WebAssembly, so the guest ran in an interpreter inside WebAssembly. WasmVM now checks the guest and translates it into a module the browser's own WebAssembly engine runs. Lean still decides every step and every DOM change.

BubblePopJS: the JavaScript engine written in Lean

Written in Lean from the ECMAScript specification. It now runs page scripts.

Stages: core language; destructuring, classes, iterators; generators; BigInt; Promises and async functions; async generators and private members; Map, Set, Reflect; for pages: regular expressions, Proxy, optional chaining, typed arrays, JSON.parse.

On the Hub, BubblePopJS is compiled to WebAssembly with the engine. It does not run there yet (its evaluator needs more stack than WebAssembly gives it), so the Hub runs QuickJS-NG.

What pages can use

Timers, animation frames, microtasks and Promises; clicks and pointer events with coordinates; taps on SVG shapes; createElement and createElementNS; selectors matched by Lean; DOMParser; MutationObserver; forms, checkboxes and radio buttons; layout reads such as clientWidth and getBoundingClientRect; WebGPU and WebGL drawing, each command checked by Lean.

Not yet: module scripts and fetch from scripts, so the ObservableHQ notebooks the rest of the Hub uses do not run here; the innerHTML setter; Range and TreeWalker; lone surrogates in strings.
