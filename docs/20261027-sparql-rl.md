# 2026-10-27 — SPARQL 1.2 RL in Lean 4

Issue: https://github.com/danbri/factoidal/issues/1099 (SPARQL-RL for 0.20.0).
Draft: https://w3c.github.io/data-shapes/sparql12-rl/ (vendored at
`third_party/testing/sparql-rl/spec/`, data-shapes commit fe4eed4).

## What changed

`formal/lean4/L4Factoidal/SPARQLRL/` implements the editor's draft:

- `Syntax.lean`: the abstract syntax (terms, triple patterns and templates,
  rule elements: triple pattern, FILTER, NOT / NOT DATA, SET, GROUP with
  COUNT / COUNT DISTINCT / MIN / MAX / SUM; rules with WHERE / WHERE DATA;
  data blocks; imports), run-once rules, well-formedness (`vars(S, i, V0)`),
  the rule dependency graph with open and closed edges (pattern/template
  unification), and the draft's stratification algorithm.
- `Parser.lean`: the grammar `sparql-rl-grammar.bnf` over the SPARQL 1.2
  tokenizer; expressions through `SPARQL.pExpr`. One triples grammar with a
  mode for data, template and pattern. Paths `/` `^` expand to triple patterns.
- `Eval.lean`: `infer` per § "Rule Set Evaluation": strata in order, run-once
  rules once, general rules to a semi-naive fixpoint. FILTER and SET use the
  SPARQL 1.2 expression evaluator; an error in SET drops the solution. WHERE
  DATA / NOT DATA match the base graph. Imports through a loader parameter.
- `Tests.lean`: `#guard`s (worked example, group aggregation, SET error,
  paths, triple terms, imports, rejections).

`SHACL/Rules.lean` is now four names over the new module (the runner's API).
The string scanners and the CONSTRUCT translation are gone.

## Choices where the draft is open

Recorded in the module headers:
- Group elements follow the draft's algorithm as written: the group pattern
  starts from the solution restricted to the keys; no solution, no group.
- Generalized triples (literal subject, allowed in DATA by the grammar) stay
  in the evaluation graph and are left out of the returned `Graph`.
- Data-block blank nodes share one scope per document; each imported
  document has its own.
- NOW() is the `EvalEnv.now` value the caller passes (one value per
  evaluation); with none, NOW() is an error.
