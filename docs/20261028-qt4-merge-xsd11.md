# QT4 XPath 4.0 branch merged with XSD 1.1 (2026-10-28)

Branch `claude/qt4-xpath-merge206`: the XPath 4.0 / F&O 4.0 work of
https://github.com/danbri/factoidal-core/pull/205 merged with XML Schema 1.1
(https://github.com/danbri/factoidal-core/pull/206) and XSLT streaming
(https://github.com/danbri/factoidal-core/pull/213). Tracking:
https://github.com/danbri/factoidal/issues/1101.

## Design: one schema path

All schema-aware work goes through `Env.schema` (`XPath4.SchemaHook`), which
`XSD11.schemaHookOf` fills from a schema. XPath 4.0 does no validation of its
own.

- `SchemaHook.declared` gives the parser (`PCtx.schemaDecl`) the in-scope
  element and attribute declarations. `schema-element(N)` and
  `schema-attribute(N)` with no declaration for `N` are XPST0008; with no
  schema in scope there is no declaration. A wildcard there is XPST0003.
- `SchemaHook.validateFnNs` validates the XML results of `fn:json-to-xml`
  (`validate`) and `fn:analyze-string` against the F&O 4.0 result schemas
  (`XSD11/FnSchemas.lean`, the test-suite copies under the W3C software
  licence). A test environment that imports the `fn` namespace with no file
  gets those schemas.
- `SchemaHook.typeInfo` describes a type of the in-scope schema for
  `fn:schema-type` and `fn:node-type-annotation` (name, base, primitive,
  variety; `constructor` validates the lexical form).
- Construction of XDM from a PSVI drops the whitespace text nodes of
  element-only content (`XSD11.XPathHooks.PNode.toXdm`).
- `fn:transform` with the requested property `xsl:supports-streaming` runs
  the XSLT Streaming 4.0 analysis of PR 213 (XTSE3430).

## Merge with XSLT 4.0 (PR 217)

- `fn:transform` has two entries in `XSLT4/FnTransform.lean`: main's
  `fnTransformHost` (packages; l4xslt4) and PR 205's `fnTransformQ` (option
  checks, requested properties, streaming check; l4qt4). Main's entry gives
  86 pass on qt4tests fn-transform (XPath mode) against 121 for
  `fnTransformQ`, so both stay until they are one function.
- In a stylesheet, `SCx.schemaDecl` accepts every name by default; the
  imported schema is checked when the test runs.
- `Doc.ofNodes_child_kinds` and `child_star_agree` (PR 205) now take the
  hypothesis that the node table is below `nsBase` (PR 217 puts namespace
  nodes above it).

## Bridge theorems

`XSD11/XPathBridge.lean`: `docOfKids_skip`, `docOfKids_validate`,
`validateFor_ok`, `parseXml_validate`. With the in-scope schema of
`schemaHookOf s`, the document that `fn:parse-xml` and `fn:doc` make under
`xsd-validation` is `XSD11.validateFor s` on the document element of the
`XML.Parser` tree; when that succeeds, the document is the XDM document of
the PSVI of `validateElement`, and the PSVI erases to the parsed element.
`#print axioms`: propext, Classical.choice, Quot.sound.

## Known gaps (fail today, https://github.com/danbri/factoidal/issues/1101)

- Atomic values carry built-in types only: `atomic-type-annotation-101` to
  `-103`, `node-type-annotation-103`, `fn-load-xquery-module-050`
  (`cast as` a schema type).
- `use-xsi-schema-location` in `fn:doc` does not load a schema:
  `fn-doc-40-065`, `fn-doc-available-40-065`.

## Conflicts between the two test suites

The vendored qt4tests (qtspecs of 2026-10-28) and xslt40-test disagree on
seven tests that pass on main and fail on this branch. The branch follows
qt4tests, the XPath 4.0 target:

- extensible records `record(.., *)` and `?` on record fields are
  XPST0003 in qt4tests (RecordType-007, "extensible record were dropped";
  "optional fields were dropped"): xslt40-test record-004, -009, -027,
  type-alias-012;
- a leading `/` or an axis step on a non-node is XPTY0004 in XPath 4.0
  (qt4tests K2-Axes-38a, PathExpr-J-013): xslt40-test error-XPTY0020a,
  -XPTY0020b, analyze-string-085 expect XPTY0020;
- `declare namespace p = ""` undeclares `p` (qt4tests
  K-ExtensionExpression-5, XPST0081): xslt40-test use-when-4003 expects
  XPST0017.
