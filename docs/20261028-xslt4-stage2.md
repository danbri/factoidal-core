## Mechanisms that are not obvious from the code

- **Keyword arguments of stylesheet functions.** `XPath4.Env.hostParams`
  gives the parameter names of a host function by name and arity. The
  evaluator places keyword arguments by name before it calls the host
  function (XPath 4.0 §4.5.1.1).
- **Copies keep accumulator values.** `XPath4.Doc.origin` of a copied
  tree holds the document number of the original, the original index of
  each copied node, and the original nodes when they are a run-time tree.
  `accumulator-before` and `accumulator-after` map a node of a copy to its
  original (XSLT 4.0 §18.2.3: `fn:copy-of`, `fn:snapshot`, `xsl:copy-of
  copy-accumulators="yes"`). `XSLT4.withOrigin` builds the map, also
  through `fn:snapshot`'s copied ancestors.
- **Applicable accumulators** (§19.2): the documents of the initial match
  selection use the `use-accumulators` of the initial mode, and an
  `xsl:source-document` its own attribute; other trees take all
  accumulators. The rules are a variable after the global variables
  (`vAccRules`), so template calls keep them. Otherwise XTDE3362.
- **Run-time namespaces.** An instruction whose element declares
  namespaces runs in `Instr.withNs`, so `format-number`, `key`,
  `function-available` and the other functions that read a lexical QName
  at run time use the bindings of that element (§5.1.1). A variable under
  such a wrapper still binds its following siblings (`peelVar`).
- **`xsl:apply-imports`** considers the template rules of the modules that
  the current rule's module imports: `Tmpl.precLo` is the lowest
  precedence in that module's import subtree (§6.8). In 4.0 it and
  `xsl:next-match` pass on the parameters of the current rule
  (`Ctx.supplied`, `v4` on the instruction).
- **Mode result types** (§6.6.3): the result of a rule with no `as` and of
  the built-in rule is coerced to the `as` of `xsl:mode`; XTSE4040 checks
  rule types statically with `XPath4.subtype`.
- **CDATA text** (§11.4.3): `xsl:text cdata` and `xsl:value-of cdata`
  surround their text with two marker processing instructions
  (`piCdataStart`, `piCdataEnd` in `XPath4/Serialize.lean`), as
  `disable-output-escaping` does; the xml and xhtml methods write the text
  between them as CDATA sections and do not write the markers.
- **Messages** are document nodes (`TResult.msgDocs`); a dynamic error in
  the content of a message with `terminate="no"` does not stop the
  transformation (§23.1). The runner evaluates `assert-message` over them.

## Theorems (`XSLT4/Theorems.lean`)

Proved, no `sorry`; `#print axioms` gives `propext`, `Classical.choice`
and `Quot.sound` only:

- `partsFrom_matches`, `analyzeParts_substrings`, `analyzeParts_groups`:
  `xsl:analyze-string` gives the records of F&O `fn:matching-segments`
  over the shared regex code.
- `numberText_single`, `formatOne_eq`: `xsl:number` with a single format
  token is the XPath 4.0 formatting function of that token.
- `copyTree_run`, `copyAsTree_nodes`, `copy_content`, `copy_structure`,
  `copyRecs_length`: a deep copy (`xsl:copy-of`, `fn:copy-of`, the
  `deep-copy` built-in rule) has one node for each node of the source
  subtree, with the same kind, name and value, and the same children and
  attributes at the same relative indices (§11.9.2).

Open (https://github.com/danbri/factoidal/issues/1149): agreement with the
XSLT 1.0 engine on the XSLT 1.0 fragment, the identity transform over
`run` (the copy theorems above cover the copy primitive only), and
well-formed serialized output. These are `#guard`s and differential runs
today (`l4xslt4 --xslt10 DIR`).

## What is not done

- Test sets that are not vendored: `misc/docbook`, `unicode-90`,
  `fn/json-to-xml`.
- `unparsed-entity-uri` (the XML document type has no system identifiers),
  `load-xquery-module`, `collection` and `uri-collection`, the
  `xsl-stylesheet-processing-instruction` feature, package version
  resolution `lowest_version` and `unspecified`.
- `fn:transform` messages do not reach the caller's message list, and
  `fn:transform` in a static expression is not available.
- `xsl:evaluate trusted` waits for the XPath 4.0 trust level of branch
  `claude/qt4-xpath-all`.
