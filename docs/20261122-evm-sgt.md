# EVM SGT execution and proof increment — 2026-11-22

Tracking: https://github.com/danbri/factoidal-core/issues/754. Depends on draft
https://github.com/danbri/factoidal-core/pull/753 and its earlier stacked work.

## Proposed scope

The restricted EVM now admits opcode **SGT (0x13)**, with the 3-gas
very-low tier. It pops the left signed operand from the *top* of the stack,
then the right operand, and computes `b.signedLt a` on the existing full
256-bit two's-complement representation. Both operands stay within Word;
no host Int narrowing or unsigned comparison is used.

The zero-value, read-only frame's fetched-instruction policy explicitly
admits SGT. Unsupported environment opcodes are still refused.

## Intended theorems and precise boundaries

The statements were recorded in issue #754 before the executable edit.

- `EVMCleanroom.Word.signedGt_dual` is a definitional equality of the
  actual helper and reversed SLT, for arbitrary 256-bit words.
- `EVMCleanroom.step_sgt` connects the *actual Core.step dispatcher* to
  the common atomic commit, with SGT's exact operand order and 3-gas
  requested charge. Gas/stack failures are handled by `commit`.
- The existing `EVMCleanroom.Word.signedLt_correct` theorem in
  `SolidityProofs.lean` establishes the signed-value ordering used here.
  This is compositional internal proof evidence, **not** proof of EELS
  refinement, full-fork conformance, account-state execution or consensus.

Expected printed axiom sets (must be checked with pinned Lean 4.33.1
on the PR source before being called measured): `[]` for `signedGt_dual`
and `[propext]` for `step_sgt`. The active v2 evidence manifest pins
all modified executable, policy, tests and oracle-driver blobs.

## Independent executable checks

`scripts/differential/solidity-pure.mjs` adds an 8×8 matrix (64 SGT
cases) spanning signed minimum, signed maximum, zero, positive words
and negative encodings, plus the separate one-gas-short and
stack-underflow-at-0/1-operand cases. Every case executes real Lean
`evm-subset --pure-frame-call` against pinned EthereumJS Shanghai
`runCode`; it compares status, gas, stack, memory and return bytes.
No JavaScript imitation of the SGT algorithm is used as an oracle.

Expected comparison count is **594 total, including 67 new SGT cases**.
These are *expected gate values*, not results until the new head has
passed the workflow.

```sh
# In the standalone project directory; use the repository's Lean build lock.
cd formal/lean4/evm-cleanroom
lake build
python3 scripts/check-active-ledger.py
python3 scripts/check-axiom-output.py
node scripts/differential/solidity-pure.mjs .lake/build/bin/evm-subset
```

Existing 10,000-case differential corpus, Prague/Cancun replay, nested
CALL and authenticated Frontier verification must be rerun on the new
source. Do not carry forward their older CI passes.

## Exclusions and performance

This change does not implement EXP, SHA3, SGT in an independently proved
fork-indexed opcode schedule, CREATE, precompiles, full transactions/blocks,
Engine API or beacon consensus. These remain part of issue #725.
No local before/after timing could be taken in the connector-only execution
environment; the CALL latency-tail regression from issue #739 remains open.
The PR must remain draft and unmerged until all required gates and review
are complete.
