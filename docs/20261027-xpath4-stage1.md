## What was built

`formal/lean4/L4Factoidal/XPath4/` is a new module tree beside the XPath 1.0
module (`L4Factoidal/XPath/`, unchanged, still used by XSLT 1.0 and GRDDL):

| File | Content |
| --- | --- |
| `Atomic.lean` | atomic values (XSD built-in type plus value), string values, shortest round-trip double/float output, casting, numeric arithmetic, comparisons |
| `Syntax.lean` | the expression tree, sequence types, items (atomic, node, map, array, function) |
| `Parser.lean` | scannerless recursive-descent parser for the XPath 4.0 grammar |
| `Doc.lean` | the XDM node table over the project's XML parser |
| `Catalog.lean` | the F&O 4.0 signatures as data |
| `Core.lean` | dynamic context, atomization, EBV, axes, sequence-type matching and subtyping, coercion, deep-equal |
| `Lib.lean` | the function library (fn:, map:, array:, math:) |
| `Grapheme.lean`, `GraphemeData.lean` | UAX #29 grapheme clusters |
| `Eval.lean` | the evaluator |

Everything is total: the parser and the evaluator take a fuel argument that
decreases on every nested call; no new `partial def`
(`tools/lean-hygiene-audit.py` reports 163, the baseline).

The runner is `formal/lean4/Harness/Qt4Run.lean`, `lean_exe l4qt4` (not a
default target). The tree is not imported by the `L4Factoidal` library root,
so the default library target, the wasm build and the npm package do not
change; `lake build l4qt4` compiles it and checks its `#guard`s.

## How a test is scored

A test case is **unsupported** when a dependency is not met: a spec
dependency without an `XP` token that includes 4.0, a feature other than
`higherOrderFunctions`, XML 1.1, XSD 1.0, a language other than English, or an
environment with a schema, schema-validated source, collection, resource,
decimal format or collation. An unsupported test is never a pass.
An `error` assertion passes only with the expected error code. An assertion
kind the runner does not evaluate (`serialization-matches`, `assert-xml` with
a file) is a fail. `--isolate 60` runs each test set in a child process with
a 60-second limit; unfinished tests count as fail.

Command (from `formal/lean4/`, with `ulimit -s 65520`):

    lake build l4qt4
    .lake/build/bin/l4qt4 --isolate 60

Measured 27 October 2026 on branch `claude/qt4-stage1` (no test set hit the
60-second limit):

| Family | Pass | Fail | Unsupported | Total |
| --- | ---: | ---: | ---: | ---: |
| prod | 7809 | 924 | 6215 | 14948 |
| op | 3708 | 79 | 1002 | 4789 |
| fn | 10036 | 4713 | 3094 | 17843 |
| map | 337 | 14 | 10 | 361 |
| array | 437 | 54 | 46 | 537 |
| math | 181 | 0 | 0 | 181 |
| **Total** | **22508** | **5784** | **10367** | **38659** |

Of the test cases that apply to XPath 4.0 (pass + fail = 28292), 79.6% pass.
Of the 5784 failures, 2915 are a call to a function this stage does not
implement (`XPST0017 ... not implemented`), 810 are tests that expect some
other error where this implementation raised `XPST0017` (mostly the same
cause), and 238 use JNodes. The per-test-set lines and every
failure reason are printed by `--list-fails`.

## Not implemented (Stage 2 and later)

Date/time formatting and parsing (`format-*`, `parse-ietf-date`,
`build-dateTime`, `parts-of-dateTime`), `analyze-string`,
`matching-segments`, `replace` with an action function, JSON/CSV/XML/HTML
parsing and conversion, serialization, `fn:hash`, `random-number-generator`,
UCA collations, `deep-equal` options, `normalize-unicode` beyond ASCII,
`unparsed-text`, `collection`, JNodes (`jtree`, `jnode()`), `but with`, `=?>`
method calls, computed node constructors, composite casts (`cast as
array(T)` / `map(K, V)`), schema types, the namespace axis.
