# SVG text in foafnaut (issue 1270)

Issue: https://github.com/danbri/factoidal/issues/1270 (SVG text and textPath in a page
made the engine refuse the whole page). Owner, 2026-11-07, verbatim: "That page says SVG
doesn't do its text, but the next page has SVG text on curves. Can we update the dataviz
to be pure SVG for text labels too?"

## How it works

- `labs/demos/foafnaut/SVG.lean` reads `text`, `tspan` and `textPath` when the caller
  gives a shaper (`PaintContext.shaper`). The HTML frontend gives one
  (`WebRender.svgShaper`), made from the font profile of the HTML text: the same Lean
  shaper (`SfntProfile`), the same word memo and the same held fonts, so fallback fonts
  work for SVG text too. A standalone SVG document has no shaper; its text goes through
  the SVG-font lowering of `SVGForgiving.lean` as before.
- The reader collects the addressable characters of a `text` element in order (SVG 2
  §11.6 white space with `white-space: normal`, or `xml:space="preserve"`), with the
  paint and text properties of the element that holds each run, and the per-character
  `x`, `y`, `dx`, `dy` and `rotate` lists (a `tspan` overrides its ancestors; the last
  `rotate` value holds for the rest of its element).
- `labs/demos/foafnaut/SVGText.lean` does the layout, with no font code: each word is
  shaped once, split into clusters, and placed. An absolute `x` or `y` starts a text
  chunk; each chunk moves by its `text-anchor`. `letter-spacing` and `word-spacing` add
  after a cluster and a space. `dominant-baseline` (and `alignment-baseline` on the same
  element) move the glyphs by the font's ascent and descent.
- `textPath` (SVG 1.1 §10.13): the path is flattened to a polyline with arc lengths. A
  run on a path is one chunk: its whole advance gives the anchor shift from
  `startOffset` (a length or a percentage of the path length). The middle of each
  glyph's advance goes to its distance along the path, the glyph turns to the tangent
  there, and a glyph whose middle is off the path is not drawn. `method="align"`,
  `side="left"` and `spacing` are read; `method="stretch"` and `side="right"` are
  refused with a message.
- The glyph outlines go to user units (the points move; no scale stays in the
  transform, so a stroke width stays in user units) and are painted as `path`
  primitives, one for each run of one style, at most 120 subpaths each.

## Checks

- `#guard`s in `SVGText.lean`: anchors, chunks, `dx`/`dy`, letter spacing, rotation,
  the glyph outline position, path length with closing and with moves, placement on a
  straight and a vertical path, glyphs past the end not drawn. Theorem
  `Polyline.at_before_start`.
- `showcase_gaps_test.ts`: the four generated and hand-written text pages render;
  text, anchors, tspan and textPath add paint.

## Not done (each has an expected failure in `showcase_gaps_test.ts`)

- Vertical `writing-mode` is laid out horizontally:
  https://github.com/danbri/factoidal/issues/1285 (vertical SVG text).
- SVG text gives no glyph runs, so it can not be selected or copied:
  https://github.com/danbri/factoidal/issues/1286 (SVG text selection).
- Not read and refused: `textLength`, `lengthAdjust`, `baseline-shift`. Read and not
  used: `font-family` (every text uses the held fonts), `font-weight` and `font-style`
  (no bold or italic face is held).

## The showcase generator

`labs/demos/foafnaut/tools/showcase-pages.mjs` replaces `showcase-pages.py`. It is plain
ECMAScript with no packages: each layout (bars, lines, tidy tree, circle packing, force
layout, lettering, tables) is a pure function from data to an SVG string, and only
`main` reads the Lean files and writes the pages, so a page script can call the same
functions in a browser. Every label is SVG `text`, `tspan` or `textPath`, so the pages
are about 6 times smaller than the glyph-outline pages.
