# YAML-LD 1.0 in Lean (2026-10-29)

Tracking: https://github.com/danbri/factoidal/issues/1165 (track A, item 2).

## What was built

- `formal/lean4/L4Factoidal/YAML/Loader.lean`: a YAML 1.2.2 loader. It parses
  a stream and composes each document directly into a JSON value
  (`L4Factoidal.JSON.Json`): block and flow collections, the five scalar
  styles, `%TAG` directives, tags, anchors and aliases, and the Core Schema
  (§10.3). It refuses what has no JSON value: non-string keys, cycles,
  `.inf` and `.nan`, tags outside the Core Schema.
- `formal/lean4/L4Factoidal/YAMLLD/Api.lean`: YAML-LD 1.0 §4 (encoding, the
  top-level check, stream processing with `extractAllScripts`), the HTML
  script rule of §6, a documentLoader for YAML-LD context documents, and the
  JSON-LD 1.1 API (expand, toRdf, compact, flatten, frame) on that value. No
  JSON-LD algorithm is duplicated: expand and toRdf call the value-level entry
  points `expandRoot` and `parseJsonLdRoot` (split out of `expandDocument` and
  `parseJsonLd`); compact, flatten and frame take the value's JSON text.
- `formal/lean4/L4Factoidal/YAMLLD/Theorems.lean`:
  `yamlld10_expand_eq_jsonld11_expand` and `yamlld10_toRdf_eq_jsonld11_toRdf`
  (a YAML-LD stream and a JSON text with the same internal representation
  expand alike and give the same dataset), the stream rule of §4.4.2, and the
  rows of the §4.3.2 scalar table.

## Scores (2026-10-29)

`bash tests/yamlld/run.sh`:

- yaml-ld suite (json-ld/yaml-ld `fafcf7ae`): 77 pass, 0 fail (out of 77); 20
  excluded (defective test data, https://github.com/danbri/factoidal/issues/1182).
- JSON superset: 2133 of 2133 `.jsonld` inputs of the JSON-LD 1.1 suite load
  through the YAML loader as the value `parseJson` gives. This is measured, not
  proved.
- Scale: 400,000-entry mappings and sequences load under a 1 MB stack.

## Decisions

1. **Defective test data.** The 19 `core-*` cases name a context document
   without an `@context` entry, which JSON-LD 1.1 API §4.1.2 step 5.2.5
   refuses; three of them also expect a top-level map with only `@id`, which
   §5.1.2 step 19.2 drops. The Extended Profile case `cir-scalar-other-2`
   contradicts its twin `cir-scalar-other-1`. Evidence:
   https://github.com/danbri/factoidal/issues/1182. The run checks the 19 with
   the context repaired (19 pass) and fails if an excluded case passes.
2. **Extended Profile.** Its text is a placeholder. The option
   `Options.extended` reads the suite's fixtures: a tag outside the Core Schema
   is dropped and the node resolved as untagged. Without it such a tag is
   `loading document failed` (§4.3.2).
3. **Null documents.** JSON-LD expansion of a `null` document now gives `[]`
   (JSON-LD 1.1 API §5.1.2 step 1 and `expand()`); it was an error. This is the
   one change to JSON-LD behaviour; the JSON-LD suites are unchanged
   (791 pass, 0 fail, 2 local-override, out of 793; toRdf 467 of 467).
4. **Duplicate keys** are kept (JSON allows them), so that JSON texts load to
   the same value through both parsers.

## Not done

- No wasm op or npm function for YAML-LD yet.
- No proof that the YAML loader extends the JSON parser; only the measurement
  above.
- No YAML-LD writer (JSON-LD to YAML-LD).
