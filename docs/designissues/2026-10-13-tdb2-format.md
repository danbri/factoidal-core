# Apache Jena TDB2 on-disk format, and a Lean reader for it

Status: 2026-10-13. Tracking: https://github.com/danbri/factoidal/issues/834
(Fuseki replacement: TDB2 databases cannot be read).

Owner, 2026-10-13, verbatim: "Work on Fuseki issues eg binary compatibility on
disk but proving our sparql is same as with other backends".

This record follows the QLever reader method (`skills/qlvr`): a format record
from the source and the observed bytes, an independent Python probe, a Lean
decoder, and tests against the other system's own output.

Source: Jena 6.2.0 source jars from Maven Central (`jena-tdb2`,
`jena-dboe-trans-data`, `jena-dboe-base`, `jena-arq`), the same release
`tools/sota-bench.py` pins (binary tarball sha256
`14c12ef4aa2f0078a473be4b10b015e0e0b85e767d6867e8581679de8fec3f6e`).
Class names below are in those jars.

## 1. Directory

A database directory `DB/` holds `tdb.lock` and one or more generations
`Data-0001`, `Data-0002`, ... . Compaction writes a new generation; the
highest number is current. Each generation holds:

| Files | What |
|---|---|
| `SPO`, `POS`, `OSP` (`.bpt`, `.idn`, `.dat`) | default-graph triple indexes, 24-byte records |
| `GSPO`, `GPOS`, `GOSP`, `SPOG`, `POSG`, `OSPG` | quad indexes, 32-byte records |
| `nodes` (`.bpt`, `.idn`, `.dat`) | node table index: 16-byte hash key + 8-byte NodeId |
| `nodes-data.obj`, `nodes-data.bdf` | node table data (Thrift terms) and its state file |
| `prefixes*`, `GPU*` | prefix table (graph, prefix, IRI) |
| `journal.jrnl` | the transaction journal; empty after a clean commit |
| `tdb.lock` | process lock |

The `.idn` and `.dat` files are memory-mapped in 8 MiB segments, so a small
database still has 8,388,608-byte files (sparse).

## 2. B+trees (`org.apache.jena.dboe.trans.bplustree`)

All integers are big-endian (Java `ByteBuffer` default order). Block size
8192.

- `X.bpt` (`BPTStateMgr`): three longs: root block id, node-block limit,
  record-block limit. 24 bytes.
- `X.idn`, tree nodes (`BPTreeNodeMgr.formatBPTreeNode`): bytes 0-3 an int,
  block type in the high byte (6 `BPTREE_BRANCH`, 7 `BPTREE_LEAF`) and key
  count in the low 24 bits; then `MaxRec` records; then `count + 1` int
  pointers. `order = ((8192 - 4 - recordLength) / (recordLength + 4) + 1) / 2`
  (`BPlusTreeParams.calcOrder`, `Gap = 0`), `MaxRec = 2·order − 1`,
  `MaxPtr = 2·order`. Order 146 for 24-byte records, 113 for 32-byte records
  (both observed with `probe_tdb2.py stats`). A branch points to nodes in
  `X.idn`; a leaf node (type 7) points to record blocks in `X.dat`.
- `X.dat`, record blocks (`RecordBufferPage`): int count, int link (next
  block, −1 at the end), then `count` records in key order.

TDB2 trees are copy-on-write: a commit writes new blocks and a new root, and
old blocks stay in the file. A reader must walk from the root in `X.bpt`; it
must not scan the `.dat` file in order. The Lean reader and the probe walk
the tree depth first with an explicit stack.

A triple index record is three NodeIds (S, P, O for `SPO`); a quad index
record is four (G, S, P, O for `GSPO`). To list the quads, `SPO` (default
graph) and `GSPO` (named graphs) are enough.

## 3. NodeIds (`NodeIdFactory.create64`, `NodeIdType`, `NodeIdInline`)

A NodeId is one big-endian 64-bit word.

| Bits | Meaning |
|---|---|
| bit 63 = 0 | pointer: byte offset of the term in `nodes-data.obj` |
| bits 63, 62 = 1, 1 | inline `xsd:double`, 62 bits (`DoubleNode62`): sign bit 61, 9-bit exponent 60..52 (rebased: `exp11 = exp9 − 255 + 1023`; 0 and 0x1FF map to 0 and 0x7FF), 52-bit significand |
| bit 63 = 1, bit 62 = 0 | inline value: type in bits 62..56, value in bits 55..0 |

Inline types used by the reader: 1 `xsd:integer` and 10-21 the derived
integer types (value: 56-bit two's complement, `IntegerNode.unpack56`); 2
`xsd:decimal` (`DecimalNode56`: 8-bit scale in bits 55..48, read unsigned;
48-bit two's complement unscaled value); 3 `xsd:float` (the 32 IEEE bits);
5 `xsd:dateTime`, 6 `xsd:dateTimeStamp`, 7 `xsd:date` (`DateTimeNode`:
milliseconds 16 bits, minutes 6, hours 5, day 5, month 4, year 13, timezone 7
in quarter hours with 0x7F = `Z` and 0x7E = none); 8 `xsd:boolean`.

## 4. Node table data (`NodeTableTRDF`)

`nodes-data.obj` is a sequence of Thrift `RDF_Term` structs in the compact
protocol (`TRDF.protocol` returns `TCompactProtocol`), with no length prefix.
A pointer NodeId is the byte offset of one struct. Field ids
(`org.apache.jena.riot.thrift.wire`):

| `RDF_Term` field | Type | Content |
|---|---|---|
| 1 `iri` | struct `RDF_IRI` {1 iri: string} | IRI |
| 2 `bnode` | struct `RDF_BNode` {1 label: string} | blank node label |
| 3 `literal` | struct `RDF_Literal` {1 lex, 2 langtag, 3 datatype, 4 dtPrefix, 5 baseDirection} | literal |
| 10 `valInteger` | i64 | integer value |
| 11 `valDouble` | double (8 bytes little-endian) | double value |
| 12 `valDecimal` | struct `RDF_Decimal` {1 value: i64, 2 scale: i32} | decimal value |

The node table writes terms with `allowValues = true`
(`ThriftConvert.convert(node, true)`): an integer of type `xsd:integer`,
`xsd:long`, `xsd:int`, `xsd:short` or `xsd:byte` that is not inlined is
stored as `valInteger`, and read back as `xsd:integer`
(`ThriftConvert.convert(RDF_Term)`).

## 5. What Jena prints for a value it stores by value

TDB2 keeps the value, not the lexical form, of every literal it inlines or
stores as `valInteger`/`valDouble`/`valDecimal`. Reading the term back
gives a lexical form that Jena computes:

| Stored | Printed by | Example |
|---|---|---|
| inline integer types | `Long.toString`, datatype from the NodeId type | `"01"^^xsd:int` → `"1"^^xsd:int` |
| `valInteger` | `Long.toString`, datatype `xsd:integer` | `"5"^^xsd:long` not inlined → `"5"^^xsd:integer` |
| inline decimal | `XSDNumUtils.canonicalDecimalStrWithDot` | `"1.50"` → `"1.5"`, `"2"` → `"2.0"` |
| `valDecimal` | `BigDecimal.toPlainString` | |
| inline double | `XSDNumUtils.stringForm(double)`: `Double.toString`, `e0` appended when there is no exponent | `"1.0E2"^^xsd:double` → `"100.0e0"` |
| `valDouble` | `Double.toString` | |
| inline float | `Float.toString` | |
| dateTime, date | `DateTimeNode.unpack` | |
| boolean | `"true"` / `"false"` | `"0"^^xsd:boolean` → `"false"` |

So a TDB2 database does not keep the RDF terms it was given: RDF 1.1
Concepts §3.3 makes `"1.0E2"^^xsd:double` and `"100.0e0"^^xsd:double`
different terms with the same value. The differential gate (section 7) sees
this on the W3C `cast` tests. A reader that must agree with `tdb2.tdbdump`
reproduces Jena's forms; `L4Factoidal/Tdb2/Format.lean` does that, including
Java's `Double.toString` / `Float.toString` (JDK 19 and later: the shortest
decimal of at least two digits in the rounding interval, the closest one on
a length tie, plain layout for 10^-3 ≤ |x| < 10^7, else `d.dddE<n>`), with
`#guard` cases checked against Java 21.

## 6. Tools and tests

| Path | What |
|---|---|
| `tools/tdb2/probe_tdb2.py` | Python probe: `stats DB`, `dump DB`, `node DB OFFSET` |
| `formal/lean4/L4Factoidal/Tdb2/Format.lean` | Jena's lexical forms (decimal, dateTime, Java double and float) |
| `formal/lean4/L4Factoidal/Tdb2/Read.lean` | B+tree walk, Thrift compact decoder, NodeId decoder, quads as N-Quads; `readDatabaseNQuads` |
| `l4factoidal tdb2-dump DIR` | every quad, N-Quads |
| `l4factoidal query DIR --format tdb2 ...` | SPARQL over the decoded quads (also `parse`, `update`, `canonicalize`) |
| `tests/tdb2/run.sh` | builds two databases with `tdb2.tdbloader`, compares the Lean dump and the probe dump with `tdb2.tdbdump`, and one SPARQL count with `tdb2.tdbquery` |

Results, 2026-10-13 (`SOTA_DL=... tests/tdb2/run.sh`, exit 0):

| Database | Quads | Lean dump = tdbdump | Probe dump = tdbdump | Count query = Jena |
|---|---|---|---|---|
| W3C: SPARQL 1.1 `functions` data, two `aggregates` files, two RDF 1.1 TriG files | 103 | yes | yes | 91 = 91 |
| `examples/wikidata/subsets/lifesci-kgx/data/sequence_variant.ttl` | 6,455 | yes | yes | 1800 = 1800 |

The Lean dump of the 6,455-quad database takes 0.04 s and 63 MB peak RSS.

Rules kept by the Lean reader: no `partial`, `sorry`, `axiom` or
`native_decide`; every loop over input-proportional data is a `for` over a
range with mutable state; the one recursive function (`readStruct`) recurses
once per Thrift nesting level, bounded by its `depth` argument; a malformed
tree (pointer cycle, block outside the file, count too large) gives an error,
bounded by a fuel of the block count; a non-empty `journal.jrnl` is refused.

## 7. Gaps

Each gap is an open issue with an expected-failure test.

- `factoidal serve --tdb2 DIR /ds` (npm CLI) and `serveStore(DIR, { tdb2: true })`
  serve a TDB2 database read only (2026-10-18, issue 834). The wasm ops
  `tdb2ServeKeys` (which generation, which files) and `tdb2ServeOpen` (decode,
  index, register a read-only served handle) are in
  `formal/lean4/Wasm/Ops/StoreServe.lean`; the host (`npm/factoidal/bin/serve.mjs`,
  `openServedTdb2`) lists the directory and reads the named files. Writes
  answer 501 (`WriteScope.readOnly` in `StoreEndpoint.lean`, with `#guard`
  cases). Test: `npm/factoidal/test/fuseki-compat.test.mjs`.
- The reader materialises every quad in memory and then queries; it does not
  answer a pattern from the TDB2 indexes on disk. The same gap for
  Shardborough is https://github.com/danbri/factoidal/issues/775.
- Not decoded: RDF 1.2 triple terms in the node table (`RDF_Term` field 9),
  prefixed datatype names (`dtPrefix`), the prefix table. The reader reports
  an error naming the field when it meets one.
- Writing a TDB2 database is not in scope.

## 8. The cross-backend differential gate

`tests/stack/backend_diff.py` answers every SELECT and ASK
`mf:QueryEvaluationTest` of the W3C SPARQL 1.1 suite (the real manifests)
with four backends over the same N-Quads bytes (the Lean engine converts each
test's data; `qt:graphData` files become named graphs): the Lean reference
evaluator, a Shardborough collection (IBK3, or IBK4 when the test has named
graphs), Jena TDB2, and Jena's in-memory dataset. Result equivalence:
booleans equal; solution multisets equal under a bijection of blank node
labels; xsd:string and simple literals equal; language tags compared without
case; numeric literals whose lexical forms differ but whose values are equal
are counted as agreements and reported in their own column; ORDER BY order
differences are reported apart, because ties allow them. Every disagreement
and every Lean refusal is listed in `tests/stack/backend_diff/expected.tsv`
with an issue or, for a Jena-side difference, the reason; the gate fails on an
unlisted one and on a listed one that no longer happens.

Run 2026-10-13 and 2026-10-18 (`SOTA_DL=... W3C_SPARQL11=... python3
tests/stack/backend_diff.py`, exit 0, about 20 minutes): 331
QueryEvaluationTests; 321 SELECT/ASK compared, 10 CONSTRUCT/DESCRIBE out of
scope.

| Pair | Agree | Disagree | Not comparable | Of the agreements: numeric lexical form only |
|---|---|---|---|---|
| Lean reference vs Lean store | 315 | 0 | 6 | 0 |
| Lean reference vs Jena TDB2 | 298 | 15 | 8 | 21 |
| Lean reference vs Jena in-memory | 309 | 4 | 8 | 16 |
| Lean store vs Jena TDB2 | 298 | 15 | 8 | 21 |
| Jena in-memory vs Jena TDB2 | 300 | 13 | 8 | 8 |

Rerun 2026-10-18, after `l4block-id-v3-query` and `l4block-quad-query` gained
`--base IRI` (the gate passes the query file's IRI) and set the evaluation
base from the query's base IRI
(https://github.com/danbri/factoidal/issues/835): the table above is that
run. On 2026-10-13 the first row read 310 agree, 1 disagree, 10 not comparable
(`functions#iri01` disagreed; `bindings#graph`, `exists#exists03`,
`property-path#pp34` and `pp35` were refused because relative IRIs in the query
could not resolve without a base). The remaining 6 not comparable are the
`service` tests, which need a live endpoint that no backend in the gate has.

- Lean reference against Jena: on every disagreement the Lean reference
  passes the W3C test (`l4w3c` on the same manifests: 187 pass, 0 fail, out of
  187) and Jena does not: `bnode01` (Jena gives two blank nodes for one
  string in one solution, SPARQL 1.1 §17.4.2.9), `plus-1-corrected` and
  `plus-2-corrected` (Jena concatenates strings with `+`), `cast-bool`
  (Jena keeps the lexical form `0`), and on TDB2 only the six `cast-*` tests
  (section 5) and six named-graph tests where TDB2 also differs from Jena
  in-memory on the same data.
- Not comparable: the six `service` tests (no endpoint; every backend
  fails) and the refusals above.

Lean theorems that relate store evaluation to the reference: the block codecs
round-trip (`IndexedBlockWireV3Theorems.decode_encode?`,
`denotes_decode_encode?`, and the V4 quad-block forms), and
`queryDatasetOf_eq` in `formal/lean4/Wasm/Ops/Query.lean` (a query over a parsed dataset equals the query
over its canonical N-Quads). There is no end-to-end theorem that a persisted
query answers what the reference answers:
https://github.com/danbri/factoidal/issues/776. The gate is the measured
substitute until that theorem exists.
