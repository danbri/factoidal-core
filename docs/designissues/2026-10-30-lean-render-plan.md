# Lean render plans and the remaining native boundary

Date: 2026-10-30. The owner requested that drawing commands remain in Lean,
with TypeScript limited to the bridge to the non-Lean host.

## Executed plan

`labs/demos/foafnaut/RenderPlan.lean` computes a closed typed plan for a window
or offscreen render. It selects shader entry points, pipeline layout/topology,
uniform byte size/usage/offset, binding indices, render-pass clear/load/store,
draw arguments, target format/usage and ordered render/copy/readback commands.
The host supplies device limits and the preferred window format. Offscreen
output uses RGBA8. The plan is compiled to a small WASM module and is consumed
by `render_plan.ts`; there is no hand-maintained TypeScript plan table.

`gpu_transport.ts` and `ui_session.ts` use that shared interpreter. `svg_gpu.ts`
now forwards to the same offscreen implementation. The CPU-to-GPU payload is
still the data and WGSL generated by the existing Lean scene compiler.

## Kernel guarantees

Accepted plans retain proofs of positive/bounded dimensions, nonempty complete
vec4 rows and uniform capacity against supplied limits. `accepted_uniform_rows`
connects float count to 16-byte rows. `bytesPerRow_aligned`,
`bytesPerRow_covers` and `readbackBytes_covers` prove 256-byte copy alignment and
capacity for every pixel. Closed descriptors and traces fix the draw arguments
and ensure submission before presentation or readback mapping.

These are properties of the actual Lean plan. They do not prove that supplied
capability facts are true, that JSON transport/interpreter execution is faithful,
or that the shader, native handles, WebGPU implementation or GPU driver obey the
plan. The host checks the actual Float32Array length and device buffer capacity.
Full WGSL semantics, raster equivalence and host fidelity are open obligations.

## Work still in the host

Persistent allocation and destruction, failure cleanup, resize handling, and
visibility/dirty-frame scheduling remain in the host. A plan's dimension proof
covers its accepted request; the current window plan is created at session start,
so it is not a theorem about later resize events. Moving the session state machine
into Lean is a separate remaining step. The driver and OS will remain external.

## Input and clipboard

The browser model owns editing, selection, cursor, focus, URI matching and
transient clipboard effects. Cocoa forwards native key metadata and committed
Unicode scalars; clipboard paste crosses as one string to avoid event-queue loss.
The host reads/writes the OS clipboard only in response to a Lean effect. Input
and clipboard tests exercise the real WASM model. The newly compiled native
keyboard/clipboard path still needs a desktop test on the target Mac.

## Validation

The initial combined build passed 51 Deno/WASM tests, 12 C coordinate checks,
12 native RDF adapter groups, nine native editor/model groups and the render
plan's native guards/proofs. Mock WebGPU tests replay a real Lean-generated plan
through the interpreter and check draw arguments, command order and readback
copy-before-unmap. Those tests do not substitute for GPU image comparisons.
