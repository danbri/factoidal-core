# RIF PRD 2013 in Lean

Date: 2026-10-29. Tracking: https://github.com/danbri/factoidal/issues/1165
(track A, item 3, second part). Specification: RIF Production Rule
Dialect, W3C Recommendation, Second Edition, 2013-02-05
(https://www.w3.org/TR/2013/REC-rif-prd-20130205/).

## Result

`bash tests/rif-prd/run.sh` (`lake exe l4rif --prd`), on the W3C PRD
manifest `PRDTests.xml` (53 Approved cases):

- 49 pass, 0 fail (out of 49 decided), 1 undecided, 3 excluded (defective
  test data, https://github.com/danbri/factoidal/issues/1031).
- PRD-only cases (`PRD_v1.22`: Assert, AssertRetract, AssertRetract2,
  Modify, Modify_loop, Retract, RDF_Combination_SubClass_5): 7 pass,
  0 fail (out of 7).
- The 37 shared RIF Core entailment cases (34 W3C, 3 corrected local
  copies in `tests/rif-local/`) give the same verdict under the PRD engine
  as under the Core engine. The run fails if one differs.
- Undecided: `RDF_Combination_Constant_Equivalence_4`, also undecided
  under RIF Core.
- The run takes about 0.1 s.

Before this work no RIF-PRD case ran in either tree.

## Inventory

46 of the 53 manifest cases are RIF Core cases (dialects Core, BLD, PRD).
The runner reads them from the vendored Core suite
(`third_party/testing/rif-core-suite/Core_v1.22`), the same files and the
same presentation-syntax reader as the Core and BLD runs. The other 7 are in
`third_party/testing/rif-prd-suite/PRD_v1.22`. That zip also repeats 3 Core
syntax cases; each case is read once.

The 6 PRD-only cases without an import are read from their RIF/XML files
(§8, the normative syntax). Three of their presentation-syntax files do
not agree with the XML (details in
`third_party/testing/rif-prd-suite/README.md`): one misspells a value, one
lacks a `]`, one writes built-ins without `External`.

## Design: a layer over the Core engine

`L4Factoidal/RIF/Prd.lean` reuses the RIF Core AST (`RIF/Syntax.lean`),
the matcher `matchFormula` with the built-ins of `RIF/Builtins.lean` and
the value identity of `groundMatch`, grounding (`groundTm`, `instantiate`)
and the fact type `GAtom`. `L4Factoidal/RIF/PrdXml.lean` reuses the term,
atom, `External`, `Equal` and import readers of `RIF/Xml.lean`.

| PRD feature (§) | Where | How |
|---|---|---|
| `Not` (§2.1.2, §2.2.1) | `Cond.not`, `matchCond` | σ matches `Not(f)` iff σ does not match `f`. Core sub-formulas of an `And` are matched as one Core conjunction first, so the Core order of built-ins and equalities applies. |
| Membership (§2.2.1) | `withMemberRule` | `o # c` matches `o # c` or `o # c'` with `c' ## c`. |
| Actions (§3.1.1, §3.2) | `Action`, `GAction`, `applyGAction` | Assert; Retract of a fact, of all slot values `Retract(o s)`, of an object `Retract(o)`; Execute. A multi-slot Assert or Retract and Modify are expanded as §3.1.1 defines them (`modifyActions`). Retract compares values with `groundMatch`. |
| Built-in actions (§6.1) | `knownAction` | `act:print`: no change to the facts. §6.1 defines no other built-in action; any other `Execute` is blocked, so no verdict is read from the run (checked in `RIF/PrdTests.lean`). |
| Conflict resolution keyword (§4.2.5, §8.5.2) | `PrdXml.groupStrategyOk` | `rif:forwardChaining` or none. §4.2.5 leaves any other keyword to agreement between producer and consumer, so a document that names one is refused, not run. |
| Local constants | `qualifyPRule`, `qualifyCond` | `rif:local` constants of the premise and of the conclusion are different symbols, as in RIF Core (`Engine.qualifyTm`). |
| Action variables (§3.1.2, §4.2.3) | `Binding`, `bindActVars` | `New()`: a `urn:rif-prd:new:k` constant that occurs in no fact. `(?v o[s->?v])`: the first matching value. No matching value has no semantics in RIF-PRD (§4.2.3); it is reported as blocked. |
| Rule instances, conflict set (§4.2.3) | `Inst`, `instVars`, `conflictSet` | An instance is a rule index and the constants of its rule variables. |
| `rif:forwardChaining` (§4.2.5) | `Hist`, `nextHist`, `refracted`, `pick` | Refraction (lastPicked < recency), then highest priority, then smallest recency, then the first instance in document order (the tie-break is the implementation's choice). Recency and lastPicked count every system state, cycle and transitional: after each atomic action the conflict set is computed again (`runActions`). |
| Priority (§4.2.5, §8.5.2) | `PRule.priority`, `PrdXml.groupPriority` | The innermost Group that states one, else 0. |
| Halting test (§4.2.6) | `cycle`, `runFrom` | Final when no instance remains after refraction. |
| Core rules (§2, §8.4.2) | `ofCoreRule` | `Forall ?x (h :- b)` is `Forall ?x (If b Then Do(Assert(h)))`; a fact is an unconditional `Assert`. |

Entailment, as the test cases use it: the goal condition is satisfied by
the final state (`entailsPrd`). Two consequences:

- A rule set with no final state has no answer. A run that reaches its
  bound (2,000 cycles) is undecided.
- Exception: a monotone rule set (only `Assert` and `Execute`, no `Not`;
  `rulesMonotone`) only adds facts (`prd2013_runActions_monotone`), so a
  goal that a reached state satisfies is satisfied by every later state.
  The run stops there with `holds`. This is how
  `Chaining_strategy_numeric-add_1` (`ex:a(?x+1) :- ex:a(?x)`, no final
  state) gets the answer of RIF Core.

Imports of the shared cases: as in RIF Core, an RDFS import is closed first
and an OWL-Direct import is decided by `RIF.OwlDirect.entailsOwlDirect`.
The imported triples are the initial facts, without the
`rdfs:subClassOf` to `##` mapping (RIF-RDF-OWL 2013 §5.1.1 condition 8 has
one direction only; the BLD record has the same finding). The combination
rules `Bld.rdfCombinationRules` (conditions 7 and 8) are added as Core rules
when the document imports a graph.

A finding of the semantics, pinned by a build-time check
(`RIF/PrdTests.lean`): `If a[d->0] Then Modify(a[d->0])` never reaches a
final state. The Retract of the Modify gives a transitional state in which
the instance does not match, so its recency starts again and refraction
does not remove it.

## Theorems (`RIF/PrdTheorems.lean`)

- `prd2013_ofCoreRule_actions`, `prd2013_ofCoreRule_cond`,
  `prd2013_ofCoreRules_monotone`: an embedded Core rule asserts its head
  under its body, and a set of them is monotone.
- `prd2013_assert_mem`, `prd2013_monotone_step`,
  `prd2013_runActions_monotone`: Assert adds its fact; Assert and Execute
  keep every fact, through all the transitional states of a cycle.
- `prd2013_retract_removes`, `prd2013_retractObj_clears`: §3.2 rules 2
  and 4.
- `prd2013_modify_single`: Modify is Retract(o s) then Assert (§3.1.1).
- `prd2013_not_refracted_unfired`, `prd2013_refracted_after_fire`: the
  refraction rule of §4.2.5.

Build-time checks (`RIF/PrdTests.lean`): priority, `New()`, slot-value
action variables, `Retract(o s)`, `Retract(o)`, `act:print`, an unknown
action, refraction across transitional states, and the XML reader on a
document with `behavior/Priority`, `INeg`, `Exists`, `Do`, `actionVar`,
`New` and a two-term Retract; document-scoped `rif:local` constants; the
refusal of a conflict resolution keyword other than `rif:forwardChaining`.
