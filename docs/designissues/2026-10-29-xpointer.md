# XPointer in Lean (track B, item 2)

Tracking: https://github.com/danbri/factoidal/issues/1165 (track B, item 2).

## Specifications

- XPointer Framework, W3C Recommendation 25 March 2003.
- XPointer element() Scheme, W3C Recommendation 25 March 2003.
- XPointer xmlns() Scheme, W3C Recommendation 25 March 2003.
- XPointer xpointer() Scheme, W3C Working Draft 19 December 2002. The
  XInclude tests use it; no Recommendation replaced it.

## Modules

- `formal/lean4/L4Factoidal/XML/XPointer.lean`: the pointer grammar (Framework
  §3.1, with the `^` escapes), shorthand pointers, the element() and xmlns()
  schemes, and the evaluation from left to right (Framework §3.3). It works on
  the XML parse tree (`XML.Document`). An ID is an attribute that the DTD
  declares of type `ID`, or `xml:id`. The module imports only
  `XML.Document`.
- `formal/lean4/L4Factoidal/XML/XPointerXPath.lean`: the xpointer() scheme.
  The scheme data is an XPath expression; the XPath 4.0 engine evaluates it
  with the document node as the context node and the xmlns() bindings. The
  engine's nodes are turned back into parse-tree nodes.
- `formal/lean4/L4Factoidal/XML/XPointerTheorems.lean`: the theorems
  `xptr2003_unknown_scheme_skipped`, `xptr2003_xmlns_never_identifies`,
  `xptr2003_element_ncname_eq_shorthand`, `xptr2003_followSteps_append`,
  `xptr2003_schemeData_escape`.

## Why the xpointer() scheme is a parameter

The XInclude processor (`XPath4/XInclude.lean`, in
https://github.com/danbri/factoidal-core/pull/230) is imported by
`XPath4/XmlParse.lean`, which the XPath engine imports. If the XPointer
module imported the engine, XInclude could not import XPointer (an import
cycle). So `XPointer.resolve` takes the xpointer() scheme as a value
(`Schemes`). A caller above the engine (`fn:doc`, a test runner) gives
`XPointerXPath.schemes`. A caller below it gives `{}`, and an xpointer() part
then identifies no subresource.

## A hit keeps the ancestors' namespace bindings

A selected element can use a prefix that an ancestor declares. Each `Hit.node`
carries those bindings (`inscope`), so that XInclude can keep the names of the
included element (XInclude 1.1 §4.5.4).

## Tests

`lake exe l4xpointer` resolves the 98 `xpointer` attributes of the W3C
XInclude test suite (2006-09-27, `third_party/testing/xinclude`) against their
targets and compares each outcome with `tests/xpointer/expected.tsv`: 98 pass,
0 fail (out of 98). The expected lines were checked by hand against the target
documents and the suite's expected outputs.

## Not done

- XInclude does not call XPointer yet. After
  https://github.com/danbri/factoidal-core/pull/230 lands, `XInclude.expand`
  calls `XPointer.resolve` in place of the resource error "xpointer is not
  evaluated", and a runner scores the 175 XInclude cases.
- The point and range additions of the xpointer() draft (`range-to`,
  `here()`, `origin()`, `start-point()`) are not evaluated. No case of the
  suite uses them.
