# DOM and HTML: WPT work of 2026-11-14

Branch `wip/dom-html`. Plan: `docs/designissues/2026-11-13-wpt-plan.md`. Every count is Chrome
subtests (the plan's scale). Baseline: the full run of main 6dde36491
(`tests/browser-wpt/wpt-full-20261113-6dde36491.json`), 71.2%.

## Step 1: `idlharness`, named access on the Window, interface objects

### What was wrong

| Loss | Count | Cause |
|---|---|---|
| Every `idlharness` test of WPT (all directories) | 39,327 Chrome subtests, 2 passed | Three defects of BubblePopJS, each hit by WPT's `resources/webidl2.js`. (1) `String.prototype.startsWith`, `endsWith`, `includes` and `lastIndexOf` ignored their position argument; the tokeniser finds punctuation with `str.startsWith(p, i)`, so no IDL parsed ("Unrecognised tokens"). (2) A sticky regular expression that fails took the steps of the whole rest of the subject, though it is tried at one index: two failures a token on `html.idl` (109 KB) used the 5 M steps of a run. (3) The decoded subject of the last match was kept for one string only, and the tokeniser tests one character (`/[\t\n\r ]/.test(c)`) between two matches on the input, so the input was decoded again for every token (quadratic: 2 s for `dom.idl`, 23 KB). |
| `x is not defined` for an element id (`html/` about 1,500; `css/` about 6,000 by the CSS agents' count) | several thousand | Named access on the Window object (HTML §7.3.3) was missing. |
| `idlharness`: "property should be enumerable", class strings | about 260 in `dom/` and `html/dom` alone | The page objects are JavaScript classes: their members are not enumerable and their prototypes had no `Symbol.toStringTag`. |
| `idlharness`: "interface object must pass IsConstructor check" | one for each interface | `new` on a Proxy threw: BubblePopJS had no `[[Construct]]` for a Proxy. |

### Changes

- `JS/Interp.lean`: `clampPos`, `unitsAt`, `lastIndexOfFrom`; the four String methods take their
  position; `startsWith` and `endsWith` on an ASCII receiver read only the units compared
  (`indexesReceiver`). A failed sticky match takes one step. `cachedChars` keeps only strings of
  `cachedCharsMin` (256) bytes or more, so a match on a short string leaves the kept subject.
- `JS/Interp.lean`: `construct` and `isConstructor` for a Proxy (`construct` trap, or the target).
- `DOM/Named.lean` (new): the named objects of a Window and the value of a named property, a
  function of the document tree. `node_query` op 180 (`Hosts/DomOps.lean`; this work uses ops 180
  to 199).
- `JS/Interp.lean` `namedGlobal`: a name with no binding (`lookup`, `typeof`), or a property that
  the global object and its chain lack (`getV`), asks the function in the global's internal slot
  (`namedGetterKey`, a private-name key). The prelude's function asks op 180 for the document of
  the running script. Only the miss path changed: a name that resolves does no new work.
- `prelude.js`: one pass over the interfaces on the global when the prelude runs (once for the
  engine): members enumerable, `Symbol.toStringTag` the interface's name (Web IDL §3.7).

### Proved, tested, open

Proved (Lean theorems, no `sorry`):

- `JS.clampPos_le`: a clamped position is at most the length.
- `JS.unitsAt_bound`: where `unitsAt` is true, the search string lies inside the subject.
- `DOM.Named.namedObjects_empty`, `value_empty`: the empty string names nothing.
- `DOM.Named.namedObjects_sound`: every named object is in the document's tree order and is
  named by one of the three bullets of §7.3.3.

Tested (`#guard`): the four String methods with positions, BMP and surrogate cases; 20,000
failed sticky matches inside 200,000 steps; `new` on a Proxy; the named-properties hook with a
script as the host; `DOM.Named.answer` on a sample tree (element, collection, frame, the
elements whose `name` does not count).

Open:

- `clampPos` equals the integer part of its argument: rests on `Float`, not proved.
- `'x' in window` and `Object.getOwnPropertyDescriptor(window, 'x')` do not see named
  properties. A frame renamed with `window.name` is not followed.
- A named-property miss walks the document once (as `getElementById` does): linear in the
  document for each read of a property the Window lacks.
- A Proxy on the prototype chain of an ordinary object is still not consulted on a miss.

## Step 2: custom elements, reflection rows, scripts that a script inserts

### What was wrong

| Loss | Count | Cause |
|---|---|---|
| `custom-elements/` | 4,381 of 4,404 | No `customElements`. |
| `html/semantics/interfaces.html`, and every test that checks an element's interface | 438 and more | An element with no class of its own (`section`, `b`, `code`, a valid custom element name) was an `HTMLUnknownElement`; HTML §3.2.2 makes it an `HTMLElement`. |
| ARIA attributes (`html/dom/aria-*`, `wai-aria/`) | about 1,450 | `role` and the `aria*` IDL attributes were missing. |
| `html/dom/reflection-sections.html` | 258 | `Document.dir`, `fgColor`, `linkColor`, `vlinkColor`, `alinkColor`, `bgColor` were missing. |
| `script-type-and-language-js*` | 436 | A script element that a script inserts did not run at all. |
| Tests in `.xht`/`.xhtml` pages | 3,703 of 4,086 | In an XML document an element in the HTML namespace was a plain `Element` (the interface was chosen by "HTML element of an HTML document"), and `createElement` in an XHTML page made elements in no namespace (the page's document had no content type): an `iframe` made by a script never loaded. |
| `dom/nodes/Document-createElementNS.html` and others that load `/common/dummy.xml` | about 250 | A `.xml` document was read by the HTML parser. |

### Changes

- `DOM/CustomElements.lean` (new): valid custom element names; the elements a tree change
  reaches, in shadow-including tree order (`node_query` 181, 182).
- `prelude.js` section customelements: the registry, `[HTMLConstructor]`, upgrades, the four
  callbacks from the tree and attribute natives (wrapped at the first `define` only), `createElement`
  with definitions and `is`, `ElementInternals`. The element's object is the `this` of its
  constructor: the HTMLElement constructor adopts it for the node being made or upgraded.
  BubblePopJS does not rebind `this` to an object that a base constructor returns, so an element
  that a script already holds when it is upgraded keeps its old object, and gets the
  constructor's own properties and prototype copied (open item below).
- `DOM/Reflect.lean`: a nullable string kind; rows for `role`, 43 `aria*` attributes, `popover`
  and `popoverTargetAction`. `reflectInstall` reads the rows of `Element` too.
- `HTML/ScriptType.lean` (new): classic, module, importmap or data from `type` and `language`
  (`node_query` 183). `prelude.js` section dynscripts: a script element made by `createElement`
  runs when connected with a source, in a document with a browsing context; `src` scripts are
  fetched with the page's `fetch` (so a cross-origin script without CORS headers fails: open).
- `prelude.js`: `htmlEl` (namespace, not document type) decides interfaces, form owners,
  activation and handler attributes; `DOM/OfXml.lean`: an XML document with an XHTML root has
  the content type `application/xhtml+xml`; a path ending in `.xml` is XML.

## Step 3: element-reflecting attributes and forms

- `DOM/ElementRef.lean` (new): "get the attr-associated element(s)" (`node_query` 184, 185) for
  `ariaActiveDescendantElement`, the seven `aria*Elements`, `popoverTargetElement`,
  `commandForElement`.
- `DOM/FormControls.lean` (new, `node_query` 186): form owner with the `form` attribute,
  `form.elements`, a select's options and selected options, labels. An option's selectedness
  set by script is kept in `Node.checkedness` (tree_op 6 now takes an option).
- `HTML/TextSelection.lean` (new, 187): "set the selection range" and `setRangeText`.
- `HTML/InputValue.lean` (new) and `DOM/FormValidity.lean` (new, 188): date, month, week, time,
  local date and time and number microsyntaxes; value to number and back; value sanitization;
  min, max, step; `stepUp`/`stepDown`; `willValidate`; the validity states valueMissing,
  typeMismatch, rangeUnderflow, rangeOverflow, stepMismatch.
- `prelude.js` section forms: `form.elements`/`length`, `HTMLFormControlsCollection`,
  `HTMLOptionsCollection`, `RadioNodeList`, the select, option, textarea, output, fieldset and
  label members, `labels`, the text selection API, `ValidityState` and the validation methods,
  `stepUp`, `stepDown`, `valueAsNumber`, `valueAsDate`, `Option`, `Image`.
- The value of an input is still its `value` attribute and a textarea's its text content: there
  is no separate dirty value, so `value` and `defaultValue` are not independent (open).

## Step 4: element states, popovers, dialogs, focus

- `DOM/Arena.lean` `Node.states`: bits that the page's objects set and selectors read: 1 a showing
  popover, 2 a modal dialog, 4 a defined custom element, 8 the focused element. Command
  `setStates` (tree_op 30; 31 reads), with the render side's JSON forms.
- `DOM/Selectors.lean`: `:popover-open`, `:modal`, `:focus`, `:focus-visible`, `:focus-within`;
  `:defined` is false for an element with a custom element name until it is defined; `:checked`
  reads the checkedness and selectedness that a script or a click set.
- `DOM/Focus.lean` (new, `node_query` 189): focusable areas, the focus target of `focus()` (with
  `delegatesFocus`), the focus delegate.
- `prelude.js` sections focus and popover: `focus()`, `blur()`, `activeElement` (retargeted),
  blur/focusout/focus/focusin; `ToggleEvent`, `CommandEvent`, `showPopover`, `hidePopover`,
  `togglePopover`, `beforetoggle`/`toggle`; dialog `show`, `showModal`, `close`, `requestClose`,
  `returnValue`, the dialog focusing steps; button `command`/`commandfor` and `popovertarget`.
- `Rendering/Style.lean` `computedFrom`: a dialog without `open` and a popover that is not
  showing start with `display: none`.

## Proved, tested, open (steps 2 to 4)

Proved:

- `DOM.CustomElements`: `reserved_refused`, `validName_local`, `validName_hyphen`,
  `validName_noUpper`, `reachGo_nil`.
- `DOM.Reflect`: `bool_roundtrip`, `nstr_roundtrip` (get after set for boolean and nullable
  string attributes), `enumGet_missing`, `enumGet_known` (an enumerated getter answers only a
  canonical keyword of its row or the invalid value default), `clampTo_bounds`, `clampTo_idem`.
- `HTML.ScriptType`: `kind_default`, `kind_empty_type`, `kind_type_wins`, `kind_empty_language`,
  `name_injective`.
- `DOM.ElementRef`: `attrElement_explicit_reachable`, `attrElements_explicit_reachable` (an
  explicitly set element is answered only when it is a descendant of a shadow-including ancestor
  of the referencing element: an element inside a shadow tree is never answered to an element
  outside it), `byId_sameTree`, `attrElement_absent`.
- `DOM.FormControls`: `single_select_at_most_one`, `formElements_owned`, `labelsOf_control`.
- `HTML.TextSelection`: `setRange_bounds`, `rangeText_range`, `rangeText_selection` (after
  `setRangeText` the selection lies inside the new text).
- `HTML.InputValue`: `stripNewlines_none`, `stripNewlines_idem`, `sanitize_color_length`,
  `defaultStep_positive`. `DOM.FormValidity`: `disabled_barred`, `willValidate_submittable`,
  `validityBits_other`.
- `DOM.Focus`: `firstFocusableGo_focusable`, `focusTarget_focusable`, `focusDelegate_focusable`,
  `disabled_not_focusable` (script can never focus a disabled control).

Tested only: the `#guard`s of each module (WPT's custom element names, script types, date and
time strings, valueAsNumber tables, e-mail addresses, selection arithmetic, selector states,
initial display of dialogs and popovers); every prelude section by the cloud WPT runs.

Open:

- The round trip `toNumber t (ofNumber t x) = x` of `HTML.InputValue` (tested on samples), and
  the calendar functions' correctness beyond the samples.
- BubblePopJS: `this` of a derived constructor is not the object its base constructor returns;
  `Reflect.set` ignores the receiver for setters; `typeof` of a Proxy of a function is "object".
- Custom elements: scoped registries and a registry for each frame's document (frames share the
  realm, so they share one registry); form-associated custom elements do not take part in form
  submission; `CustomStateSet` is not read by `:state()`; the reaction order is the order the
  natives return in, not one queue for each `[CEReactions]` call.
- Script-inserted `src` scripts: no-cors fetch, `async = false` ordering, `nomodule`.
- Focus: whether the element is being rendered is not checked; sequential (Tab) navigation;
  `autofocus`; a click does not move the focus.
- Popover: light dismiss and Esc need input events; `popover=hint`'s separate stack; top layer
  painting order.
- Sanitizer API (3.8k), Trusted Types (3.7k), innerText (1.4k), `document.open/write` on frame
  documents (quirks, 6.9k), a frame's own global (dom/ranges 3.7k): not done.
