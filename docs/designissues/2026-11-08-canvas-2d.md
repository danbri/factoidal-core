# Canvas 2D for pages, drawn by Lean

Date: 2026-11-08. Author: canvas2d, a subagent of session depmap-0e.
Related: https://github.com/danbri/factoidal/issues/1244 (WasmVM, page scripts), records
`2026-11-08-page-scripts.md`, `2026-11-08-page-gpu.md` (the canvas texture and blit this
uses) and `2026-11-08-cpu-render-backend.md`.

## 0. Status

`canvas.getContext('2d')` gives a `CanvasRenderingContext2D`. Lean
(`formal/lean4/L4Factoidal/PageCanvas/`) parses every colour and font, keeps the drawing
state, builds and flattens paths, strokes them, shapes text with the Lean shaper and the
fonts the engine holds, and rasterises every draw into the canvas bitmap. The page's
JavaScript (`tools/wasmvm/quickjs/prelude.js`, section "canvas2d") only converts arguments
and makes objects. Both script engines run it: BubblePopJS (the native default) and
QuickJS-NG in WasmVM (the Hub). Section 9 has the numbers.

## 1. The path of a frame

```
page script: ctx.fillRect(...), ctx.fillStyle = ..., ctx.arc(...), ...
  prelude.js: each call appends numbers (opcode, arguments) and strings to the batch
  end of the task (a microtask), or a call that needs an answer:
        | ONE import: gpu_command(200, header = JSON array of the strings, payload = binary64s + bytes)
        v
Lean: Hosts.Page.serveExtra -> PageCanvas.Wire.call
  Wire.decode     bytes -> Array Cmd             the display list of the batch
  Store.run       each Cmd on its canvas         Raster: coverage, paint, composite
  -> the canvas bitmap (premultiplied RGBA, width x height x 4 bytes) is up to date
        | at the end of the turn (WebScripts.turnAnswerOf): PageCanvas.Store.hostCmds
        v   for each canvas drawn in the turn: {"k":"canvas"} once, then {"k":"pixels"}
host (Hub: page-gpu.mjs; native: the same file through layer_compositor.ts)
  writeTexture of Lean's pixels into the canvas texture; the page-GPU blit draws it into
  the page layer at the canvas box Lean gives (render answer `layers.canvases`).
```

Queries (`getImageData`, `measureText`, `isPointInPath`, `isPointInStroke`, the attribute
getters, `getTransform`, `getLineDash`, `toDataURL`, `addColorStop`, `createPattern`) are
op 201: the prelude sends the waiting batch first, then the query, and gets Lean's answer.

## 2. Why the canvas is a bitmap drawn by Lean, not scene items

Canvas 2D is a bitmap API: what is drawn stays, operators such as `copy`,
`destination-in` and `xor` read the pixels already there, `clearRect` erases a part,
`putImageData` writes pixels, and `getImageData` reads them back. The scene backends of
the page (the WebGPU scene shader and its CPU form `SVGRaster.lean`) draw a scene of
items over an opaque page in paint order, with rectangle clips only; they have no
operators other than source-over, no erasing, and no transparent result to read back.
A display list replayed by them every frame would also grow without end (nothing is ever
removed from a canvas except by drawing over it).

So Lean rasterises each command into the canvas bitmap when the batch arrives
(`PageCanvas.Raster`), and the bitmap is the canvas's texture. The page's own scene does
not change when the canvas does: there is no layout and no Lean render for a canvas
frame, only the blit (as for a WebGPU canvas).

- `getImageData` reads the bitmap: no readback from the GPU and no second rasterisation.
  A frame rasterises only what that frame drew; nothing is drawn again unless the page
  draws it again.
- The CPU raster of `SVGRaster.lean` costs about 2 to 5 µs a pixel and has no alpha
  channel in its output; the canvas rasteriser here (an edge list per draw, sixteen
  sample rows per pixel row with exact horizontal coverage, and spans) costs a few
  nanoseconds a covered pixel natively.

## 3. What Lean does

| Family | Lean |
|---|---|
| State | `State.Stack`: `save`/`restore` (at most 1,024 saved), the drawing state of HTML §4.12.5.1.4: transform, clip, fill and stroke styles, alpha, operator, line styles, dashes, shadows, font, text alignment, baseline, direction, smoothing |
| Transforms | `Geometry.Matrix`: `setTransform`, `transform`, `translate`, `scale`, `rotate`, `resetTransform`, `getTransform` (a `DOMMatrix` with a to f) |
| Colours | `Color.parse?`: CSS Color 4 named colours, `transparent`, `currentcolor` (black), hex 3/4/6/8, `rgb()`/`rgba()` legacy and modern, `hsl()`/`hsla()`, `hwb()`; serialisation as HTML says |
| Styles | `Paint`: colours, linear, radial (two circles, HTML's ω rule) and conic gradients through a 1,024-entry table interpolated in premultiplied space; patterns from canvases, `ImageBitmap`s and images, with repetition and `setTransform` |
| Paths | `Geometry.Path`: move, line, quadratic, cubic, close; `arc`, `ellipse`, `arcTo`, `roundRect` (radii normalised and scaled down as HTML says), `rect`; arcs become cubic Béziers of at most a quarter turn; `Path2D`, `addPath`, and SVG path data through the engine's SVG parser (`NativeSVGPath.parse`, arcs by SVG 2 Appendix B.2.4) |
| Fill | `Raster.coverage`: nonzero and even-odd, sixteen sample rows a pixel row, exact horizontal coverage; `fillRect` with an axis-aligned transform has exact coverage |
| Stroke | `Stroke.strokePolys`: in user space, then transformed; widths, `butt`/`round`/`square` caps, `miter` (with `miterLimit`)/`round`/`bevel` joins, dashes with offset; zero-length segments pruned |
| Clip | `clip()` makes a coverage mask (one byte a pixel), multiplied into the one before |
| Compositing | `Raster.compose`: the 11 Porter-Duff operators and the 15 blend modes of Compositing and Blending Level 1 (separable and non-separable), with global alpha |
| Shadows | colour, offset and blur (three box blurs for σ = blur/2) |
| Text | `Text.parseFont?` (the CSS `font` shorthand: style, variant, weight, stretch, size with relative units against 10px, line height, family); `fillText`, `strokeText`, `measureText` (width, ink box, font box, baselines) with the Lean shaper (`SfntProfile.wordIn`) and the engine's held fonts, `textAlign`, `textBaseline`, `direction`, `maxWidth` |
| Images | `drawImage` (3, 5 and 9 arguments) from canvases, `ImageBitmap`s and the page's images (decoded by Lean's PNG, JPEG and GIF decoders from the images the engine holds); the source rectangle is clipped to the image and the destination follows; `imageSmoothingEnabled` (nearest or bilinear) |
| Pixels | `getImageData`, `putImageData` (dirty rectangle), `createImageData`, `ImageData`, `createImageBitmap` (from canvases, images, `ImageData`; crop rectangle) |
| Files | `toDataURL`: a PNG (`Png.encode`: stored DEFLATE blocks in a zlib stream, CRC-32) |
| Offscreen | `OffscreenCanvas` with `getContext('2d')` and `transferToImageBitmap` |

Off, and why:

- `toBlob` and `OffscreenCanvas.convertToBlob`: the engine has no `Blob` yet.
- `filter`: the attribute is kept, nothing is filtered.
- `currentcolor` is black: the context does not know the canvas element's computed colour.
- Non-sRGB colour spaces (`lab()`, `lch()`, `color()`), `color-mix()`: not parsed (the
  value is ignored, as an invalid one).
- `drawImage` from `<video>` and `SVGImageElement`: not sources yet.
- Fonts: text draws only with fonts the engine holds (the page's `@font-face` fonts are
  not loaded for canvases); with none held, `fillText` draws nothing and `measureText`
  gives zeros.

## 4. Theorems

`formal/lean4/L4Factoidal/PageCanvas/Theorems.lean` (axioms `propext`,
`Classical.choice`, `Quot.sound` only; `#print axioms` in the file):

| Theorem | Statement |
|---|---|
| `coverage_within`, `rectCoverage_within`, `boxOf_within` | the pixels a fill covers are inside the canvas |
| `Draw.visits_within` | the pixels a draw visits (its coverage, or the whole canvas for an unbounded operator) are inside the canvas |
| `blendPixel_outside_clip` | a pixel outside the clip region keeps its value |
| `Canvas.onBitmap_size`, `run_size` | every draw keeps the bitmap's size; after any display list, every canvas's bitmap has `width × height × 4` bytes |
| `emit_pixels` (with `emitOne_pixels`) | the host gets pixels only of the size of a canvas of the page |
| `Stack.restore_save` | `restore` after `save` gives the state before the save |
| `Stack.restore_setters_save`, `canvas_restore_save` | with any setters between them, too: a setter changes only the current state, never a saved one |

What is not proved: that the coverage is the area of the shape inside each pixel (it is
tested against Chrome, section 9), the colour arithmetic, and the shaper. `run_size` and
`emit_pixels` hold through final checks (`Canvas.fix`, the size test in `emitOne`): no
command makes a bitmap of another size, and the checks are the specification.

## 5. The wire

`PageCanvas.Wire`: header a JSON array of strings; payload a little-endian `u32` count, 4
zero bytes, the binary64 numbers, then raw bytes (image data, by offset). The opcodes are
listed in `Wire.arity`. A batch is all or nothing: an unknown opcode or a short command
refuses it (the page's console says why). Numbers in answers are JavaScript's
`Number::toString` of the Float (`JS.numToString`), which the page reads back exactly.

## 6. Cost

- A page with no 2D canvas pays nothing: the prelude makes the Canvas 2D classes on
  first use (`c2d()`), and a turn with no canvas drawn adds nothing to its answer.
- A frame of a page is one import for all its canvases (more only when a call needs an
  answer).
- Lean rasterises only the commands of the frame; `getImageData` reads the bitmap.
- The host gets the whole canvas each frame it is drawn (Base64 in the turn's JSON);
  a canvas not drawn in a turn sends nothing.

## 9. Results (2026-11-09, Apple M1, native engine library)

**Pixels against Chrome** (`canvas2d_test.ts`; Chrome 156's pixels of the 27 scenes of
`canvas2d-scenes.js`, 48 x 48 each, in `canvas2d-reference.json`): 27 of 27 scenes match on
BubblePopJS and on QuickJS-NG (a scene matches with at most 3% of its pixels off by more
than 24 in a channel; the pixels that differ are edge pixels of anti-aliasing). Exact or
nearly (largest difference 0 to 4): rectangles, gradients (linear, radial, conic), patterns,
`source-in`, `destination-over`, `xor`, `multiply`, global alpha, `drawImage`,
`putImageData`, save/restore, `Path2D` from SVG data.

**WPT** `html/canvas/element` and `html/canvas/offscreen` (the directories but `manual`,
`video`, `wide-gamut-canvas`, `global-hdr-headroom`, `layers`, `filters`; `.worker.js`

(`--wpt-root`): see the hand-back for the final count. Before (origin/main 98cc094f7): 30
