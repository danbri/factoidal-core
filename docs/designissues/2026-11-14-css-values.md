## Design

One table, generated from the grammars of the specifications, and one matcher. Every user reads the same
functions, so they can not disagree.

- `Rendering/CssValues/Token.lean`: CSS Syntax 3 tokenizer and component values. Numbers are `Rat`: no
  `Float` anywhere in `CssValues`, so values compare exactly and `calc()` arithmetic is exact.
- `Numeric.lean`: numeric leaves and the math functions (type check, simplification, serialisation).
  `numeric ctx req cv` gives the specified value with no context and the computed value with one.
- `Grammar.lean`: the value definition syntax read from text into a grammar `G`, and `matchG`, a
  list-of-successes matcher bounded by fuel. Its output is the canonical value: keywords in lower case, the
  parts of `||` and `&&` in grammar order, numbers and colours canonical. With a context in the environment
  the same matcher gives the computed value. Commas are omissible as CSS Values 4 §2.1 says. `<position>` is
  a native leaf. Table notation `a=b` gives a keyword its canonical form (`xyz=xyz-d65`).
- `Color.lean`: CSS Color 4 and 5 in exact rational arithmetic (conversions to and from lab, lch, oklab,
  oklch and the wide-gamut spaces are rational series approximations to 10 decimals, said so in the file).
- `Data.lean`: generated by `tools/css-values/gen-properties.py` from `third_party/mdn-data` (mdn-data
  2.37.2, CC0-1.0) and `tools/css-values/supplement.json` (hand-maintained: newer properties, non-negative
  ranges, Chrome's serialisation order, legacy aliases).
- `Properties.lean`: `specified p v`, `supports p v := (specified p v).isSome`, `expand` (shorthand to
  longhands), `recombine` (longhands to shorthand), `computed ctx p v`.
- `Declaration.lean`: the CSSOM declaration block as a list of longhand declarations, read from and written
  to text. The block of `element.style` is the `style` attribute: there is no second copy of the state.
- `Rendering/ComputedGeneric.lean`: `getComputedStyle` for every property of the table: the cascade of that
  one property over the matched rules and the inline style (the order of `CSS.computedFrom`), inheritance,
  `var()` substitution, then `CssValues.computed`. It runs only when a script reads a computed style.
- `Rendering/CssSheet.lean`: the rules of a sheet text, `insertRule`, `deleteRule`, selector and rule text.
- `Rendering/CssTyped.lean`: CSS Typed OM: reification, serialisation, numeric types, arithmetic. A numeric
  typed value is the `Calc` tree of `Numeric.lean`.
- Glue: `DomOps` ops 151 (style block), 152 (computed style names), 153 (sheets), 154 (typed values);
  `WebDocument.measure` answers op 200+k through `ComputedGeneric.valueAt`; `prelude.js` holds only the WebIDL
  surface (objects, argument checks, exceptions).

## Decisions that change behaviour

- `CSS.supports` now answers for the parser, as CSS Conditional 3 says, not for the layout profile. A property
  that parses and is not laid out (`display: grid`) is "supported". Style sheets' `@supports` rules were not
  evaluated through this function and are unchanged. This is the standard's meaning and what the tests
  measure; a page that feature-tests layout with `CSS.supports` will take the branch the layout does not do.
- `element.style` refuses invalid values and writes canonical text to the `style` attribute. The layout
  profile reads the same attribute as before; the canonical forms it meets are ones it read before
  (`rgb(r, g, b)`, lengths, keywords, the `margin`/`padding`/`border` shorthands).
- A sheet changed through CSSOM (`insertRule`, `deleteRule`, a rule's `style`) is written back as the text
  of its `style` element, in canonical form, so the cascade sees it. A script that reads the element's text
  afterwards sees the canonical sheet. Not what browsers do; it keeps one copy of the state.
- For a keyword or colour property of the layout profile that the element itself declares, the computed
  value is the declaration's (so `display: grid` computes to `grid`, and a colour keeps its alpha).

## Performance

- A page that does not call `element.style`, `getComputedStyle`, `CSS.supports`, CSSOM sheets or Typed OM
  runs no new code: the cascade and layout do not use the table. The table is static data (701 rows of
  string literals); grammars are parsed when a value is read.
- Stack: every loop over input is a fold or a tail call. What recurses is nesting, bounded by constants
  (64 levels of functions and blocks, grammar depth 96, 256 ancestors); each remaining recursion is in
  `tools/lean-tail-recursion-allow.txt` with its bound.
- Cost of one `style` operation: the block's declarations are parsed again (the state is the attribute).
  Measured numbers are below.

## Proved, tested, open

Proved (theorems, kernel-checked; axioms `propext`, `Quot.sound`, `Classical.choice` only):

- `toLower_idempotent`, `lower_idempotent`: keyword canonicalisation is idempotent.
- `NumReq.clamp_inRange`, `NumReq.clamp_idempotent`: a computed `calc()` clamped to a range is in it, and
  clamping twice is clamping once.
- `supports_iff_specified`: `CSS.supports` is the parser (one function).
- `expand4_collapse4`, `collapse4_expand4`: the shortest form of a four-sides shorthand expands back to the
  same four values.
- `Block.find_put`, `Block.find_remove`, `Block.find_put_other`: a declaration block answers what was set,
  nothing for what was removed, and is unchanged for other properties.
- `insertRule_length`, `insertRule_index`, `deleteRule_length`: the rule list operations change the length
  by one, and an index past the end is refused before the rule text is looked at.
- `addTypes_self`, `numType_neg`: Typed OM numeric types.
- Colour (18): clamping and byte lemmas, `hexPair_roundtrip`, `parseHex_bytes`, `parseRgb_bytes`,
  `hslToRgb_grey`, `hwbToRgb_grey`, `namedColors_bytes`, hue fix-up, `mixPair_alpha`.

Tested only (`#guard`s, and the local corpus of 44,122 cases collected from the WPT parsing tests):

- That the canonical value of a grammar parses back to itself (serialise∘parse idempotent) for the property
  grammars. It is proved for the leaves above, not for the matcher over an arbitrary grammar.
- Shorthand expansion then recombination for `border`, `font`, the pair and any-order shapes.
- `calc()` simplification preserving the value.
- The approximate colour conversions and the alpha serialisation rule.
- The `prelude.js` glue (only by the WPT runs).

Open:

- Shorthands with no generic shape (`background`, `grid*`, `flex`, `animation`, `transition`, `mask`, the CSS
  Gaps shorthands) are kept whole: they parse and round-trip, their longhands read as "".
- `calc()` holding non-math functions (`anchor()`), `sin()` and the other transcendental functions as values,
  per-combination omission of defaults (gradients, shapes), `<custom-ident>` exclusions.
- Computed values that need layout or the font (`ex`, `ch`, percentages, `grid-template-*` on a grid).
- `getComputedStyle(el).getPropertyValue('--x')`: the measure call has no string argument.
- Sheets of `link` elements have no rules in CSSOM; nested group rule edits rewrite the parent rule.
- A proof that `matchG` accepts exactly the language of the grammar.

## Second part: the cascade on real style sheets (from 05:00 UTC)

Eight live pages drawn by the engine showed little effect of their style sheets. Reading
one test sheet and the sheets of seven of those pages (1.36 MB, 9,119 style rules) through
the cascade's reader showed why, on the cascade's side:

| Cause | What it was |
|---|---|
| Sheet size | `parseRaw` read the first 131,072 characters, and a document's sheets are joined into one text first (`WebDocument.sheetSource`): everything past 128 KB of all sheets together was not read. |
| Block at-rules | Only a top-level `@media` was entered. `@supports`, `@layer`, `@media` in `@media` and `@container` blocks were skipped whole. |
| Nesting | A nested rule was read as a declaration named `&`. |
| Declarations | Split at every `;` and `:`: `url(data:image/png;base64,...)` ended the declaration; `margin: calc(1px + 2px)` was split at its spaces. |
| Custom properties | `var()` was never substituted in the layout cascade: `color: var(--x)` was dropped. 1,806 of the 9,119 rules use custom properties or `var()`. |
| Flow-relative properties | `margin-inline-start`, `inline-size`, `padding-block` ... were unknown to the layout profile (227 distinct declarations in the seven pages). |
| Selectors | `:has()`, valid pseudo-elements (`::selection`, `::marker`, `::placeholder`, `::-webkit-...`), `:read-only`, `:dir()` made `DOM.Selectors` refuse the selector, and one refused selector drops its rule. |

What remains after this work is the layout profile itself (positioning, flex, grid,
per-side borders, font weight, floats, negative margins, `white-space`): agents `pages`
and `layout`.

### Design

- `Rendering/SheetReader.lean`: one reader of sheet text for the cascade. `scan` (a tail
  call per character) cuts the text into pieces at the `{`, `}` and `;` outside strings and
  blocks; `read` goes over the pieces with the open rules on a list and gives `Leaf`s: a
  style rule with its selector list (nesting resolved by `nest`), its declarations, the
  query lists of every `@media` around it, and its cascade layer with the layer's place in
  the layer order (`rankOf`); or another at-rule as written (`@font-face`, `@keyframes`,
  `@import` ...). `@supports` blocks are entered when the condition holds, evaluated by
  `Rendering/SupportsCondition.lean`: the evaluator behind `CSS.supports`, moved below
  `Style` so that sheets and scripts get one answer. `@container`, `@scope`,
  `@starting-style` and `@document` blocks are skipped. `imports` gives the `@import` rules
  of a sheet for a host to fetch (not fetched yet).
- Cascade keys: `CSS.ruleKey` and `CSS.inlineKey` (importance; origin and context;
  element-attached; layer position; specificity; order), compared by `CSS.lexLE`, used by
  `computedFrom` and by `ComputedGeneric.cascaded`.
- `Rendering/CssVars.lean`: `Computed.vars` holds the element's custom properties
  (inherited; a persistent map, shared with the parent when the element declares none).
  `resolve` adds the element's own winning declarations, references between them resolved
  in passes, cycles left without a value. `substitute` replaces `var()` in the text of a
  winning declaration before the profile reads it. `margin`, `padding`, `inset` and the
  axis shorthands that mention `var()` are kept whole and stand for each of their sides in
  the cascade (`sidesOf`, `expandSides`).
- `Rendering/CssValues/Logical.lean`: the flow-relative sides as physical sides for every
  writing mode and direction, and the property names of the logical property groups. The
  layout cascade maps winning flow-relative declarations to physical ones by the element's
  direction (`physicalWinners`); `getComputedStyle` answers a flow-relative name as the
  physical property of the element's flow, and cascades the two names as one property.
- `DOM/Selectors.lean`: `:has()` with relative selectors (the combinator kept on the first
  compound; `matchFrom` checks the leftmost compound against the anchor), pseudo-elements
  that are valid and match no element, with what may follow them, input states read from
  attributes, `:heading`, `:dir()`.

### Decisions that change behaviour

- `@supports` rules in sheets are now evaluated, by the parser's answer (as
  `CSS.supports`): a sheet's `@supports (display: grid)` block applies though grid layout
  is not done yet. This is what CSS Conditional says and what an author expects of a
  browser that parses the value; until layout has the feature, the block's rules reach a
  layout that ignores them.
- A sheet of up to 8 MiB is read (all sheets of a document together). Cost below.
- At the top level a `;` no longer ends a selector: `a; b { }` is one invalid rule, as CSS
  Syntax says (it was the rule `b`).
- A pseudo-element ends its complex selector and is refused in `:not()` and `:has()`
  (`::before.a`, `::before div`, `:not(::before)` were accepted by `querySelector`).

### Performance (native, Apple M1, one core)

| | before | after |
|---|---|---|
| Sheet of 127 KB, 721 rules | 18 ms, 60 rules read (the rest had combinators the old reader refused) | 24 ms, 721 rules read |
| Sheet of 1.28 MB, 7,201 rules | 18 ms, 62 rules read (the first 131,072 characters) | 230 ms, 7,201 rules read: reader 89 ms, selectors 83 ms, declarations and flags the rest |

A sheet is read once per text (the engine keeps the last eight). In the cascade a page
with no custom property, no `var()` and no flow-relative property pays one test of two
Bool fields per matched rule, and for each `style` attribute declaration a search for
`(` and a length test. `:has()` costs the elements in the relation of its argument for
each element tested; rules are still put in buckets by their rightmost compound.

### Proved, tested, open (second part)

Proved:

- The cascade order: `lexLE_refl`, `lexLE_total`, `lexLE_trans`, `lexLE_antisymm` (a total
  order on keys); `ruleKey_order` (declarations met at different places never tie, so the
  winner does not depend on the order of comparison); `inlineKey_wins`.
- Layers: `layerPosition_normal_unlayered`, `layerPosition_important_unlayered`,
  `layerPosition_normal_later`, `layerPosition_important_later`; `rankOf_unlayered`,
  `rankOf_pos`; `keyLT_irrefl`, `keyLT_asymm`.
- Reader: `scan_length` (every character of a sheet is in exactly one piece), `nest_top`,
  `parseInBlocks_eq` (filtering by media conditions before or after reading the rules
  gives the same rules), `ruleHolds_iff`.
- Variables: `CssVars.value_plain`, `Vars.apply_plain`, `substituted_plain` (a declaration
  without `var()` is not changed), `resolve_nil` (an element that declares none has its
  parent's).
- Flow-relative: `side_logicalOf`, `logicalOf_side`, `side_injective` (a bijection of
  sides in each of the ten flows), `block_inline_perpendicular`, `blockStart_vertical`,
  `side_initial`, `physicalWinners_plain`, `physicalNameOf_plain`.

Tested only (`#guard`): the reader on 30 sheets (nesting, layers, `@supports`, strings,
escapes, sheets that stop early); 55 cascade cases; `var()` substitution and resolution
(26); the name mapping for every flow-relative name in all ten flows, and back; 52
selector cases.

Open:

- `@import` is not fetched: the host must call `SheetReader.imports` and splice.
- `@container` and `@scope` are not evaluated (their rules never apply).
- A property that is invalid at computed-value time falls to the profile's built-in user
  agent value, not to `initial`.
- The layout cascade maps flow-relative properties by direction only (it lays out
  horizontal lines); `getComputedStyle` maps by the writing mode too.
- `:has()` on a selector with no class, id or type in its rightmost compound is tried on
  every element with all its descendants: quadratic on such a selector.
- `:dir()` does not follow the directionality of form control values or slots.
- No proof that `SheetReader.read` gives the rules of the CSS Syntax grammar; that
  `substitute` terminates is by fuel, and its result is tested, not proved.

## Third part: the regressions of the first check, and more CSSOM

The check of the 23 commits on main d799500c7 (10,374 names, against that commit's full
run) gave +6,311 subtests with 122 tests worse (-890). The losses fell in three groups:

1. False passes that a correct answer removes: the css-mixins, `if()`, `attr()`,
   `random()` and `env()` tests compare two custom properties through
   `getComputedStyle`; both were '' before custom properties had computed values.
2. Bugs, fixed here:
   - A shorthand read by its parts (`byGrammar`) when an alternative of its grammar
     holds keywords or types outside any `<'property'>`: `white-space: pre` was read as
     the initial values, `block-step: none` written back as `down`, `grid-template` areas
     and `grid: auto-flow ...` refused. `tightAlternatives` keeps only the alternatives
     that name their parts, `keywordLonghands` gives the legacy `white-space` keywords
     their longhands, and a value of any other alternative keeps the shorthand whole.
   - `font: 12px/1.5 Georgia` was not read by the layout cascade at all (and
     `getComputedStyle(...).font` came from the parent): `fontLonghands`.
   - A chain of custom properties that doubles at each step exhausted memory (a
     crash): substitution stops at `CssVars.maxValueBytes`.
   - Pseudo-element pairs, `:has()` in `:has()`, `*::before` serialisation,
     `selector()` lists, `@keyframes` names, typed values on the axis shorthands,
     `float` of an absolutely positioned box, `flex: 0 1 1`.
3. Layout tests where more CSS is now read than the layout lays out (`block-size` and
   the flow-relative sizes apply; `stretch` and the keyword sizes are the layout's).

New since: `revert-layer` and `revert` roll back in `getComputedStyle`; a shorthand with
`var()` gives its longhands after substitution; registered custom properties from
`@property` rules (initial value, inheritance, computed value by the syntax);
`CSSPropertyRule`; An+B, `@scope` preludes and namespace prefixes in `selectorText`;
comments in selectors; `mediaText` of malformed queries; gap rule lists with
`repeat()`; `inset()` radii; the types of relative colour components; `progress()`.

### Proved, tested, open (third part)

longhands), `tightAlternatives_oneOf` (the reading by parts keeps only alternatives of the
table's grammar that it can read), `winningF_not_revert` (the cascaded value is never
`revert` or `revert-layer`).

Tested only (`#guard`): shorthand serialisations (white-space, block-step, grid, rule,
corner: 15), the font shorthand in the cascade (3), the doubling chain, selector pairs and

Open:

- `CSS.registerProperty` is checked but its registration does not reach computed values:
  the measure of a page sees the document, and a registration made by a script is not
  in it yet (the spec keeps it on the document: a document-level field, or a command,
  is the next step).
- The resolved values of `top`/`left`/`bottom`/`right` need the layout's containing
  block (getComputedStyle-insets-*).
- `ch` and `ex` use the 0.5em fallback, not the font's glyphs.
- Infinity and NaN in `calc()` are kept as written.
- A colour with alpha is opaque in the layout profile (the paint model has no alpha).
