# RELAX NG in Lean (track B, item 3)

Tracking: https://github.com/danbri/factoidal/issues/1165 (track B, item 3).

## Specifications

- RELAX NG Specification, OASIS Committee Specification 3 December 2001.
  ISO/IEC 19757-2:2008 restates it.
- Guidelines for using W3C XML Schema Datatypes with RELAX NG, OASIS
  Committee Specification 7 September 2001.
- James Clark, "An algorithm for RELAX NG validation" (2002): validation by
  derivatives.
- RELAX NG Compact Syntax, OASIS Committee Specification 21 November 2002
  (https://relaxng.org/compact-20021121.html; its errata page lists no
  errata). ISO/IEC 19757-2:2008 Amendment 1 restates it.

## Modules

All under `formal/lean4/L4Factoidal/RelaxNG/`:

- `Syntax.lean`: the simple syntax of §5 (name classes, patterns, the grammar
  of defines) and the `after` pattern of the derivative algorithm.
- `Names.lean`: the name character classes of XML 1.0 Fourth Edition
  Appendix B. The test suite uses them (U+0E35 must not start a name).
  `XSD.isNCName` uses the Fifth Edition classes, which accept U+0E35.
- `Simplify.lean`: the schema reader. It parses the XML syntax, checks the
  §3 grammar of the schema, applies §4.1 to §4.21 in order and checks the §7
  restrictions. `externalRef` and `include` load their targets through a
  function `String → Option String` that the caller gives, so the module does
  no IO.
- `Datatypes.lean`: the built-in library (`string`, `token`) and the XSD
  library. The XSD library reuses `XSD.SimpleType` and `XSD.Datatypes`
  (`valueOf`, `valEqualOrIdentical`). Each param is a facet, as the
  Guidelines say. `enumeration`, `whiteSpace`, an unknown param, a repeated
  param, or a facet that does not apply to the type makes the schema
  incorrect. A QName or NOTATION value is the pair (namespace URI, local
  name), resolved in the context of the pattern.
- `Validate.lean`: validation by derivatives. A `ref` is looked up only when
  a start tag is matched against it. Instance names are expanded with the
  in-scope namespaces. `xmlns` attributes are not attributes for RELAX NG.
- `Compact.lean`: the compact syntax, as its Appendix A specifies it.
  `preprocess` does A.2.2 to A.2.4 (byte order mark, newline normalization,
  `\x{N}` escapes; a newline marker is kept apart from a `#xA` that an
  escape gives, because only the second is allowed in a literal in one
  quote). `lex` makes the tokens of A.2.5 by longest match. The parser reads
  the BNF of A.1 and builds its translation, a sequence of XML elements,
  with every named constraint of A.1 (prefixes, duplicate declarations and
  attributes, annotation names, "single element"). The operators `|`, `,`
  and `&` cannot be mixed without parentheses, and `datatypeName - pattern`
  takes no operator and no repetition. Annotations become foreign elements
  and attributes; on `value`, `param` and `name` the annotation elements
  follow the element (§5.1). `translate` writes the result as an
  `XML.Node` tree: RELAX NG elements in the default namespace and the
  declared prefixes (not those bound to `inherit` or `""`) on the document
  element, as the `element()` function of A.1 requires. `simplifyCompact`
  is §6.1: `simplifyNode` of the translation, with every compact schema
  that `include` and `external` name translated through the resolver.
  `strictForm` is the §6.2 test (strict equivalence: the forms after pass 1
  and 2 with the `ns` of §4.9 made explicit; annotations are not compared)
  and `looseEq` a sufficient §6.3 test (the simplified grammars are equal
  once the contexts of `value` patterns are removed; definitions are not
  reordered or renamed).
- `CompactTheorems.lean`: `rncc2002_validator_via_xml` (§6.1: a compact
  schema is simplified as the XML syntax schema of its translation),
  `rncc2002_applyAnnotationsGroup_unit` and
  `rncc2002_applyAnnotationsChoice_unit` (the A.1 equations for an empty
  annotation), `rncc2002_looseEq_refl` and `rncc2002_looseEq_start`.
- `Theorems.lean`: `rng2001_nullable_choice`, `rng2001_nullable_group`,
  `rng2001_notAllowed_group_absorbs`, `rng2001_notAllowed_choice_unit`,
  `rng2001_empty_valid`, and two theorems that relate the XSD datatype library
  of RELAX NG to the XML Schema module: `rng2001_xsd_data_sound` (a string
  that `data` accepts is valid for `XSD.validate` of the same type and facets)
  and `rng2001_xsd_data_iff` (`data` accepts a string exactly when
  `XSD.valueOf` gives a value and, for QName and NOTATION, the prefix
  resolves).

## Tests

`lake exe l4relaxng` runs James Clark's `spectest.xml` (jing-trang
`a6bc0041`, `third_party/testing/relaxng`, provenance in its
`PROVENANCE.md`). Each check is one case: an incorrect schema is refused, a
correct schema is accepted, a valid document is valid, an invalid document is
invalid. 965 pass, 0 fail (out of 965): 213 incorrect schemas, 172 correct
schemas, 289 valid documents and 291 invalid documents. CI runs it in
`verify-lean4.yml`.

The same executable runs `compacttest.xml` (same commit, 87 test cases):
87 pass, 0 fail (out of 87). An incorrect compact schema (31 cases) must
be refused; each is refused for the reason its case tests (an A.2 escape
or literal error, an A.1 constraint, or a §4.16 name class error of the
translation). A correct one (56 cases) passes when its translation is
strictly equivalent (§6.2) to the XML schema of the case, or when both
simplify to loosely equivalent grammars (§6.3). The first test is needed
because ten schemas of the suite are not correct full RELAX NG schemas (a
top-level `empty`, `value` or `data`, which §7.1 prohibits; a `ref`
outside a `grammar`; a `grammar` with no `start`); the second because four
XML schemas of the suite were written by Trang, which leaves out a `group`
that §4.12 removes and the `text` of an `attribute`.

Expected failures (`xfailCases`; a case that passes is STALE and fails the
run): `dtdcompat-duplicate-id`, for
https://github.com/danbri/factoidal/issues/1199.

## Not done

- RELAX NG DTD Compatibility (ID, IDREF, IDREFS checks; attribute default
  values): https://github.com/danbri/factoidal/issues/1199, expected-failure
  case `dtdcompat-duplicate-id`.
- Datatype libraries other than `""`, the XSD library and (after
  https://github.com/danbri/factoidal/issues/1199) the compatibility
  library: a schema that uses one is refused, which §4.16 permits for an
  unknown library.
- The derivatives are not memoized, and there is no npm or wasm op:
  https://github.com/danbri/factoidal/issues/1200. No scaling test measures
  the memoization cost yet; that issue starts with one.
- The relation to XML Schema 1.1 is through the datatype library only
  (`rng2001_xsd_data_sound`, `rng2001_xsd_data_iff`). RELAX NG patterns and
  XSD complex types are not related by a theorem.
