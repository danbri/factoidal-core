# Networking, storage and SVG for WPT (2026-11-14)

Branch `wip/net-svg`. Plan: `docs/designissues/2026-11-13-wpt-plan.md`. Area: `fetch`,
`referrer-policy`, `content-security-policy`, `mimesniff`, `mixed-content`, `xhr`, `FileAPI`,
`cors`, `cookies`, `webstorage`, `svg`, and two leads of `2026-11-13-wpt-small-fixes.md`.
Every number is Chrome subtests passed, from `branch-wpt.yml` (Linux engine built from the
branch, the names given, against the newest full run of main as baseline).

## Root causes found

| Area (lost) | What it was |
|---|---|
| `webstorage` (1.3k) | `localStorage` and `sessionStorage` did not exist. |
| `svg` `NO_RESULT` (228 tests) | A `.svg` URL was read with the HTML parser, so the document's `script` elements were foreign content and never ran. SVG `script` elements were not script elements anywhere. |

| `svg/interact` `transparent` (234) | `fill="transparent"` was an unsupported colour: the whole picture was refused. |

The remaining timeouts (649 tests) need script-inserted `script`, `img` and `a` requests, which never load. |

## Changes

Lean, new modules (each typechecks alone; all loops are core list combinators or tail calls):

- `Net/Storage.lean`: Web Storage areas by origin and kind, in memory, 5 MiB an area; ops 80–85.
- `WHATWG/MimeType.lean`: parse, serialize, extract from `Content-Type` values, the JavaScript
  and JSON groups, the `nosniff` decisions.
- `Net/FetchRules.lean`: what a `Headers` object keeps for its guard, a `Request`'s method; ops 86–89.
- `Net/BlobUrls.lean`: blob URLs, each its origin's; ops 90–91. `Net/PageFetch.blobStep` answers a
  request for one in the engine, with `Range`.
- `Net/ReferrerPolicy.lean`, `Net/Csp.lean`: decision functions with their theorems. Not called:
  the engine sends no `Referer` and does not enforce CSP.
- `JS/JsonText.lean`: the reading `JSON.parse` uses, as a function of its own.
- `Net/Cookies.lean`: a cookie jar for `document.cookie` only (RFC 6265bis: dates, domain and
  path matching, the attributes, the `__Secure-` and `__Host-` prefixes); ops 96–97.
- `DOM/SvgValues.lean`: the values the SVG DOM reflects (a length with its unit type, a number,
  a number list, a transform list); ops 92–95.

Lean, changed: `Hosts/WebApi` (ops 80–97), `Net/Xhr` (blob store, `blobOf`), `Hosts/Dom`
(`create_node` kind 15: `writeFrameDocument`), `Hosts/LeanJSWorkers` (`scriptAccepted` with

is a comment for the SVG reader), `WebRenderScript` (SVG `script` elements), `WebScripts`
(frame navigations to `blob:` URLs), `SVG` (`transparent`), `SVGText` (character cells).

Prelude (`tools/wasmvm/quickjs/prelude.js`, the WebIDL surface): `Storage`, `StorageEvent`,
`QuotaExceededError`; `Headers`, `Request`, `Response` and the body mixin by the standard;
`fetch` over them; `FileReader`; `URL.createObjectURL/revokeObjectURL`; `document.cookie`; the SVG
element interfaces and value objects, made from one table (`svgSpec`); the `Origin` interface; a frame's window posts
to that frame's target and a frame script's `window.on…` is the frame's; `document.open`,
`write`, `writeln`, `close` on a frame's document; SVG elements have `style`, `dataset`,
`focus`, `blur`.

Hosts: the WPT runner loads a page's `@font-face` fonts for layout and passes
`X-Content-Type-Options` for worker scripts; the desktop host's script-session layout request
has the page's images and failed sheets (it had the sheets and web fonts).

## Frames of another origin (security fix)

Found while reading why `iframe-tag` tests wait for ever. `LeanJS.loadFrame` and
`Page.Session.loadFrameP` asked `Hosts.Dom.frameScriptsInRealm` before the new document was
attached, so the answer came from the origin the frame had before the navigation. A frame
that was `about:blank` (its parent's origin) or same-origin and then went to another origin,
by a `src` set after insertion, by a form, or by a redirect the embedder followed, had that
document's scripts run in the page's realm, with the page's document, storage and windows in
reach. The origin was corrected only afterwards (`navigatedTo`), and for a redirect never,
because the embedder named only the URL asked for.

Now:

- `attachDocument` takes the response URL from the embedder (`responseUrl` of the script
  session's `frame` action) and records the origin of that URL. The WPT runner sends it. A
  host that follows redirects itself and does not send it still gives a redirected document
  the origin of the URL asked for: the desktop and Hub hosts do not answer `frame` actions
  today; one that starts to must send `responseUrl`.
- The scripts that run in the page's realm are `Hosts.Dom.realmScripts` of the state after
  `attachDocument`. Theorems: `realmScripts_needs_access` (no script of a document the page
  may not reach is given to the realm), `navigatedTo_frame` (the frame kept for the element
  after a navigation is the one of the URL, whatever was kept before).
- A document of another origin whose sandbox allows scripts gets a script session of its
  own (`WebScripts.crossFrameSessions`), as sandboxed `srcdoc` frames had: its own arena and
  heap, an eighth of the page's instruction budget, no network and no frames of its own, at
  most 16 such sessions a page. It reaches its parent only by `postMessage`
  (`HTML.FrameSessions.exchange`, `exchange_out`, `exchange_data`).

Not typechecked on this machine (`Hosts/Dom.lean`, `LeanJS.lean` and `WebScripts.lean` need a
build of their imports): the cloud compile is the check, and `navigatedTo_frame`'s proof was
tried on a small model of the same definitions first.

## Decisions that are security or privacy

- Storage and blob URLs are named by the session's page origin, which the engine holds; no
  operation takes an origin from a script. An opaque origin has no storage.
- Nothing is written to disk. A persistence policy is not decided.
- The engine still sends no `Referer`, no cookies and no credentials, and reads no `Set-Cookie`.
- A cookie a script sets is its host's: the host and the secure flag are the session's page's.
  A script cannot set or read an `HttpOnly` cookie, cannot set a `Secure` cookie from a page
  that is not secure, and cannot set a cookie for a domain its host does not domain-match.
  There is no public suffix list in the engine: a `Domain` that is a public suffix is
  accepted, which is harmless only while cookies are never sent and each jar is one page
  session's. The list is needed before cookies reach the network.
- `navigator.cookieEnabled` stays `false`: the engine does not keep cookies for a site.
- `document.write` reaches only a frame the realm may already reach (`frameAccessible`).
- A request for a `blob:` URL never reaches the host (`plan_send_net`).

Known limit, flagged: frames of one page share the page's script realm and its page origin
in `WebApi.State`, so a same-realm frame of another origin would use the top page's storage
and blob URLs. Today only same-origin frames run in the page's realm (`frameAccessible`,
`frameScriptsInRealm`); a frame with a realm of its own (`HTML.FrameSessions`) has its own
`WebApi.State`. If that changes, the origin passed to `Net.Storage.op` must be the calling
document's.

## Proved, tested, open

Proved (Lean theorems, each with "Says" and "Does not say" in its doc comment):

- Storage: `op_partition`, `op_answer_local`, `op_noninterference`, `op_opaque`,
  `setItem_quota`, `getItem_setItem`; the association-list laws under them.
- JSON: `jsonParseText_strict` (a text the strict RFC 8259 parser accepts has that parser's
  value), `jsonParseText_error`.
- WebCrypto: `generateKey_refused`, `importMade_refused` (a name that is not an implemented
  algorithm gives an error and no key).
- CORS: `corsOk_credentials_wildcard`, `corsOk_needs_header`.
- MIME: `nosniff_never_script`, `nosniff_blocks_script`, `nosniff_blocks_style`,
  `computedType_nosniff`, `parse_nonempty`; workers: `scriptAccepted_nosniff`.
- Headers and methods: `validate_request_keep`, `validate_response_keep`,
  `validate_immutable`, `method_ok`.
- Blob URLs: `resolve_origin`, `revoke_other`, `add_other`, `resolve_add`, `add_bounds`,
  `Xhr.blobOf_own`, `blobRange_within`, `plan_send_net` (extended).
- Frames: `writeFrameDocument_needs_access`.
- Cookies: `visible_host`, `visible_not_httpOnly`, `visible_secure`, `admit_keeps_host`,
  `parse_keeps_host`, `set_keeps_host`.
- SVG values: `parseLength_type`, `unitType_le`, `arityOk_names`.
- Referrer Policy (not called): `determine_cases`, `determine_no_credentials`,
  `strict_cross_origin_no_path`, `strict_downgrade_none`, `noReferrer_none`,
  `sameOrigin_cross_none`.
- CSP source lists (not called): `allows_mono_append`, `allows_mono_cons`, `allows_nil`,
  `allows_none`, `self_allows_own`.

Tested only: the `#guard`s of each module (the WPT cases they come from are named there); the
955 cases of WPT's `mime-types.json` and `generated-mime-types.json` against
`MimeType.canonical` (run outside the build: all agree); the prelude classes, by the WPT runs.

Open:

- CSP is not enforced (3.2k subtests, and a page's policy is ignored). `Net/Csp.allows` is the
  check; the calls from script, style, image and connect requests are not made.
- `Referer` is not sent. Sending it by `ReferrerPolicy.determine` needs the calling document's
  URL (a frame's request must name the frame, not the page) and the page's policy from its
  header or `meta`; about 500 `fetch/api/redirect` subtests and sites that check `Referer`.
- Cookies: `Set-Cookie` is not read and no `Cookie` header is sent, so a site's login does not
  work and the `cookies` tests that set cookies by a response fail; `test_driver.delete_all_cookies`
  is not answered. No public suffix list.
- SVG DOM: `getTotalLength`, `getPointAtLength`, `getCTM`, `getScreenCTM`, the text content
  methods and the SMIL interfaces are missing; `animVal` is `baseVal`.
- Named access on the window (`id` as a global) is off: BubblePopJS does not consult a proxy in
  a prototype chain.
- The desktop host passes no `Content-Type` and no `X-Content-Type-Options` for worker scripts.
- The Hub host does not fetch linked style sheets at all.
- The WPT runner holds no default font.
- Script-inserted `script` elements do not run; `img` and `a` requests made by script do not load.
- Scripts in markup written by `document.write` do not run; the page's own document is not written.
- Storage events are not fired (they go to other documents of the origin).
- `Origin.isSameSite` throws for two different hosts: registrable domains need a public suffix
  list, which the engine does not have.
- A frame's own session (another origin, or a sandboxed `srcdoc`) has no network, no frames
  and no layout reads; a link or form in it that would navigate it is not followed.
- Risks (`skills/lean-risk-flags`): none new. No crypto, no fallback from a verified path. The
  shared-realm limit above is a property assumed, not shown, for cross-origin frames in the
  page's realm; it is stated in `Net/Storage.lean` and here.
