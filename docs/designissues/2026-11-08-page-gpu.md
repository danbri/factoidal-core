# A GPU API for page scripts, validated by Lean

Date: 2026-11-08. Author: pagegpu, a subagent of session depmap-0e.
Related: https://github.com/danbri/factoidal/issues/1244 (WasmVM, page scripts),
records `2026-11-08-page-scripts.md` and `2026-11-08-event-loop.md`.

## 0. Goal and status

Page scripts in Foafnaut run in QuickJS-NG inside WasmVM, the Lean WebAssembly VM, and
every DOM change is a typed command that Lean checks. This record extends the same rule to
the GPU: a page may draw with

- (A) a WebGPU subset: `navigator.gpu` and `canvas.getContext('webgpu')`;
- (B) WebGL 1 and WebGL 2 (`getContext('webgl')`, `getContext('webgl2')`), rewritten onto
  the same WebGPU subset.

Nothing a page asks for reaches the real GPU unless Lean has parsed it into a typed
command, validated it, and re-emitted it. Section 4 lists the theorems that hold in this
change; section 5 lists what no theorem can cover. Section 9 says what runs today.

## 1. Threat model

The attacker is the author of a page (scripts, shaders, data). The assets are: other
origins' pixels and data, the browser's own chrome and pages (the Hub's layer textures,
the address bar, other tabs), the memory of the host process and the GPU driver, and the
availability of the machine.

| Threat | What it looks like | Where it is stopped |
|---|---|---|
| T1 Reading other origins' pixels, or chrome | A shader samples, or a copy reads, a texture that holds another page, a cross-origin image, or the chrome; or a page reads back its own canvas after drawing such a texture into it | Page objects live in a per-page table; a page names objects only by its own small integers. No command reads back (no `mapAsync`, no copy to a mappable buffer, no `readPixels`, no `toDataURL` in this slice). Lean composites the page canvas into the page layer; script never sees composited pixels. Later, sampled images carry a taint label (section 4.6). |
| T2 Out-of-bounds memory | A draw reads past a vertex buffer; a shader indexes past an array; `writeBuffer` writes past a buffer | Lean checks every `writeBuffer` range and every draw's vertex range against buffer sizes; the WGSL that reaches the GPU indexes only through `min(u32(i), N-1)`; there are no storage buffers, pointers or runtime-sized arrays in the subset. The host WebGPU's own robust access stays on as a second line. |
| T3 GPU hangs, exhaustion, denial of service | A shader loops forever; a page allocates gigabytes; a page submits a million draws a frame | The shader subset has no `loop`/`while`, only `for` loops with literal bounds, no recursion (WGSL has none) and a static cost bound per invocation. Per-page quotas on bytes, objects, draws per submit, vertices per draw and canvas size. |
| T4 Uninitialised memory disclosure | A new buffer or texture shows the previous owner's bytes | Lean emits `clearBuffer` right after each `createBuffer`; each render pass on a page canvas uses `loadOp: clear`. (WebGPU also zero-fills; Lean does not rely on that alone.) |
| T5 Timing side channels | A page times GPU work to learn about other content, or uses the GPU as a high-resolution timer | No timestamp queries, no occlusion queries, no `onSubmittedWorkDone` promise resolution timing beyond the frame; the page's clock is Lean's virtual clock (event loop), coarse and advanced by the host. Not provable; mitigated (section 5). |
| T6 Driver and compiler bugs | A valid shader crashes the driver or the shader compiler, or a driver mis-bounds-checks | The subset is small and re-emitted from Lean's AST, so odd syntax (deep nesting, huge literals, unusual attributes, Unicode identifiers) never reaches the compiler. Not provable; mitigated (section 5). |

Out of scope here: physical attacks, a malicious host browser, Rowhammer through GPU
memory (mitigated only by the quotas and by the absence of storage writes).

## 2. The layering

```
page script (QuickJS in WasmVM)
  navigator.gpu / canvas.getContext('webgpu' | 'webgl' | 'webgl2')   prelude.js, page-facing JS only
        | one import per command: foafnaut_dom.gpu_command(canvas, op, bytes, len, out, cap)
        v
Lean: L4Factoidal.PageGpu                                            formal/lean4/L4Factoidal/PageGpu/
  Wire.decode      bytes -> typed Command (bounded sizes)
  Wgsl.parse       WGSL text -> AST (fuel-bounded, depth-bounded)
  Wgsl.validate    AST in the subset? (InSubset, theorem validate_sound)
  Wgsl.harden      index clamping (theorem harden_clamped)
  Model.step       per-page object table, quotas, bounds -> host commands
  Wgsl.print       the AST printed again: the only WGSL the GPU sees
        | the turn answer of scriptSession: "gpu": [host commands, JSON]
        v
host (Hub: docs/web/hub/foafnaut/layers.mjs page-gpu replay; native: section 9)
  replays the host commands on its real WebGPU device, into a page canvas texture
  per <canvas>; draws that texture into the page layer at the rectangle Lean gives
  (render answer `canvases`) with Lean's blit WGSL; composites as before.
```

The prelude is the only JavaScript on the page side; it builds no decision. It packs
arguments and throws the error Lean answers. The host replay is a switch over the host
command kinds; it decides nothing either (every id, size, offset and shader text is
Lean's). There is no JavaScript copy of the validator, and there is no fallback: an
engine without the op answers "unknown" and the canvas stays blank with a page error.

Isolation: the host keeps one table of page GPU objects per page session, keyed by Lean's
ids. The engine's own objects (layer textures, the composite pipeline, plan buffers) are
not in that table, so no page command can name them. A new page session starts with an
empty table (`State.empty`).

## 3. The WebGPU subset (slice 1)

Commands (`PageGpu.Command`):

- `configure canvas w h`: the page canvas texture, `rgba8unorm`, at most 2048 x 2048,
  usage `RENDER_ATTACHMENT | TEXTURE_BINDING` (never `COPY_SRC`).
- `createBuffer id size usage`: size at most 16 MiB and a multiple of 4; usage a subset
  of `VERTEX | UNIFORM | COPY_DST` (never `MAP_READ`, `MAP_WRITE`, `COPY_SRC`, `STORAGE`,
  `INDEX` in this slice).
- `writeBuffer id offset bytes`: offset and length multiples of 4, inside the buffer.
- `createShaderModule id code`: parsed, validated, hardened; at most 64 KiB of text.
- `createRenderPipeline id module vertexEntry fragmentEntry buffers topology`: the vertex
  layouts (stride at most 2048, at most 8 buffers, at most 16 attributes, formats
  `float32`, `float32x2`, `float32x3`, `float32x4`), `triangle-list`, `triangle-strip`,
  `line-list`, `point-list`; target format `rgba8unorm`.
- `createBindGroup id pipeline buffer`: binding 0 of group 0, a uniform buffer.
- `renderPass canvas clear draws`: `loadOp: clear` always; each draw names a pipeline,
  an optional bind group, vertex buffers, `vertexCount`, `instanceCount`, `firstVertex`,
  `firstInstance`. This is the whole of a command encoder's pass and its `submit`.

The WGSL subset (`PageGpu.Wgsl`):

- Module scope: `struct` declarations (members `f32`, `i32`, `u32`, `vecN<f32>` and the
  `vec2f`..`vec4f` forms, `mat2x2f`..`mat4x4f`, fixed `array<T, N>` with N at most 1024,
  and member attributes `@location(n)`, `@builtin(position)`); at most one
  `@group(0) @binding(0) var<uniform> name: T;`; `const` declarations; `@vertex` and
  `@fragment` functions. No `storage`, `workgroup` or `private` variables, no textures,
  samplers, atomics, pointers, `override`, `enable`, `diagnostic`, or compute entry points.
- Entry parameters: `@location(n)` inputs, `@builtin(vertex_index)`,
  `@builtin(instance_index)`, `@builtin(position)` (fragment).
- Statements: `let`, `var`, `const`, assignment and `+= -= *= /=`, `if`/`else`, `return`,
  blocks, and `for (var i = A; i < B; i++)` (also `<=`) with integer literals A and B,
  B - A at most 256, and the counter not assigned in the body. No `loop`, `while`,
  `break`, `continue`, `discard`, `switch`, or calls to user functions.
- Expressions: literals, names, unary `- !`, binary arithmetic, comparison and logic,
  member access and swizzles, indexing, type constructors, and a list of builtin
  functions (`sin`, `cos`, `tan`, `abs`, `min`, `max`, `clamp`, `mix`, `step`,
  `smoothstep`, `sqrt`, `pow`, `exp`, `log`, `floor`, `fract`, `dot`, `cross`,
  `length`, `normalize`, `distance`, `reflect`, `select`, `atan2`, `sign`).
- Limits: nesting depth 64, 4096 AST nodes per function, static cost per invocation at
  most 1 000 000 (a loop body counts once per iteration).

Lean does not type-check WGSL; the host's WGSL compiler does. Lean decides that the
module is in the subset and re-emits it; the compiler then rejects ill-typed code (an
error comes back to the page through the device's error scope as `GPUValidationError`
in a later slice; today the host logs it and the canvas is not drawn).

## 4. What Lean proves

Proved in this change (`formal/lean4/L4Factoidal/PageGpu/Theorems.lean`; axioms
`propext`, `Classical.choice`, `Quot.sound` only; no `sorry`, `native_decide` or
`bv_decide`). Section 9 gives file and line.

4.1 Subset. `validate_sound`: when `validate m = true`, the declarative predicate
`InSubset m` holds (every statement, expression, type, builtin and loop is of the
subset). The host receives only `print (harden m)` for such an `m`; `harden_inSubset`:
hardening keeps the module in the subset.

4.2 Bounds. `harden_clamped`: every index expression of a hardened module is
`base[min(u32(i), N-1u)]` where N is the declared length of the base (array, vector or
matrix) — so it is in bounds whatever `i` is. `step_write_in_bounds`: every emitted
`writeBuffer` lies inside its buffer. `step_draw_in_bounds`: for every emitted draw and
every vertex buffer it uses, the last vertex read ends inside the buffer.

4.3 Zero initialisation. `step_create_clears`: a page `createBuffer` emits exactly
`createBuffer` then `clearBuffer` of the same id, so no page-visible byte is read before
it is written by the page or zeroed. Every emitted render pass clears its target
(`step_pass_clears`).

4.4 Quotas. `run_quota`: for any command sequence, from the empty state, the page's
buffer bytes, canvas bytes and object count stay at most their limits, whatever is
refused along the way. Each submit has at most `maxDraws` draws and each draw at most
`maxVertices` vertices times instances.

4.5 Termination. `validate_cost`: a validated module's every entry point has static
cost at most `maxCost`; with no recursion (WGSL forbids it and the subset has no user
calls) and only literal-bounded `for` loops, each invocation runs a bounded number of
operations. A draw is then bounded by vertices x instances x vertex cost plus covered
pixels x fragment cost.

4.6 No readback and taint. `step_no_readback`: no emitted command has a usage or a kind
that lets anything copy out: buffers never get `MAP_READ` or `COPY_SRC`, canvas textures
never get `COPY_SRC`, and the host command type has no copy-out or map kind. The answer
the page gets from each import is a function of its command sequence alone (Lean never
sees GPU memory), so GPU contents cannot flow back into script. Taint (for later slices
that sample images): each texture gets a label `{page, origin, chrome}`; `copyExternalImageToTexture`
and texture sampling propagate labels through the command graph (a render pass's
output label is the join of the labels of everything it samples); a readback is
emitted only when the label is the page's own origin. Slice 1 has no texture input, so
every page canvas carries the page's own label; the general theorem is planned with the
texture slice.

4.7 Isolation. `step_refs_owned`: every object id in an emitted command belongs to this
page (`Gid.page = s.page`) and was created by an earlier command of the same page.

## 5. What cannot be proved, and the mitigations

- Driver, compiler and hardware bugs. Lean proves facts about the commands and the WGSL
  text it emits, under a model of WebGPU semantics. A wrong GPU driver, a buggy Tint or
  naga, or faulty hardware can break any of them. Mitigations: the subset is small;
  the text is Lean's printing (no attacker-chosen spelling); quotas limit what a bug
  can be fed; the host's WebGPU validation and robust buffer access stay on.
- That the printer is faithful. `print` is Lean code, tested, not proved to agree with
  the WGSL grammar; the clamping theorem is about the AST.
- Timing side channels. A page can still time its own frames (requestAnimationFrame
  deltas, the event loop's virtual clock as the host advances it). Mitigations: no
  timestamp queries, no `performance.now()` finer than the event loop clock, results of
  GPU work never return to script, and quotas limit how much work a probe can do.
- Real-time limits. Static cost bounds the work, not the wall time: a fragment shader
  of cost 10^6 over a 2048 x 2048 canvas is bounded but slow. Mitigations: the host's
  device-lost handling (a hung device is lost and the page canvas is dropped), the
  per-submit draw quota, and a lower cost limit for large canvases (planned).
- WebGPU's own guarantees (zero-fill, robust access) are assumptions about the host, not
  theorems; Lean adds its own clears and clamps so the slice does not depend on them.

## 6. WebGL 1 and WebGL 2 onto the same layer

One GLSL front end in Lean (`PageGpu.Glsl`), for GLSL ES 3.00, with GLSL ES 1.00 accepted
as its smaller dialect (`attribute`/`varying`, `gl_FragColor`, `texture2D`): the 1.00
forms are parsed to the same AST as their 3.00 forms. The front end translates to the
`PageGpu.Wgsl` AST, so every theorem of section 4 covers WebGL shaders with no new proof
of bounds or termination: a WebGL program is a WGSL module that `validate` accepts.

The prelude's `WebGLRenderingContext` and `WebGL2RenderingContext` keep GL state in
JavaScript only as the page sees it (the bound buffer, current program, enabled
attributes); every object creation and every draw is a Lean command. Lean keeps the
real state machine:

| GL feature | WebGPU mapping through Lean |
|---|---|
| Buffers, `bufferData`, `bufferSubData` | `createBuffer` + `clearBuffer` + `writeBuffer`; a resize is destroy + create |
| Programs (`attachShader`, `linkProgram`) | GLSL to WGSL; link checks varyings by name and type; `getAttribLocation` / `getUniformLocation` answered by Lean from the AST |
| Loose uniforms (`uniform*`) | One uniform block per program, laid out by Lean (std140-like WGSL layout); each `uniform*` call is a `writeBuffer` into it |
| GL state (blend, depth, cull, viewport, scissor, colour mask) | Folded into the pipeline key; Lean keeps a pipeline cache per program and state; `viewport`/`scissor` are pass commands, clamped to the canvas |
| `drawArrays`, `drawElements` | A render pass on the canvas (load, not clear, after the first pass of a frame); `drawElements` checks every index against the bound buffers' vertex count in Lean (the index data is in Lean's copy) or uses WebGPU robust access for large buffers with the draw clamped |
| Uniform buffer objects (WebGL 2) | `uniform` blocks map to WGSL uniform structs; `bindBufferRange` checked against the block size |
| Integer types, `flat` interpolation | WGSL `i32`/`u32` and `@interpolate(flat)` |
| Instancing (`drawArraysInstanced`, `vertexAttribDivisor`) | `stepMode: instance` vertex layouts; the instance range bounds-checked like the vertex range |
| Multiple render targets (`drawBuffers`) | Several page-owned colour targets; only target 0 is composited; the others are page textures that may be sampled |
| 3D and array textures, sampler objects | Page textures with dimension `3d` / `2d-array`; sampler objects map to WebGPU samplers (clamped LOD, no comparison until depth textures); every texture carries a taint label |
| Vertex array objects | A Lean record of vertex layouts + bound buffers; binding a VAO selects it, no GPU object |
| Transform feedback | Emulated: the vertex shader's outputs are written by a generated WGSL vertex or compute pass into a page-owned storage buffer at `min(index, capacity-1)`; Lean adds that one storage-write form to the subset, with the write index clamped (same `harden_clamped` shape) and the buffer counted in the quota |
| Textures from images, `texImage2D` | Only same-origin or CORS-approved images; label propagation as in 4.6 |

No safe mapping, refused with `INVALID_OPERATION` (or the WebGL 2 equivalent) and a
console message:

- `readPixels` in formats other than `RGBA`/`UNSIGNED_BYTE` from a page-labelled
  framebuffer; and `readPixels` of anything labelled cross-origin (the same rule as a
  tainted 2D canvas). The allowed form is a Lean-issued copy into a staging buffer
  whose result is returned through the event loop as a task, not synchronously.
- Synchronisation and timing queries: `fenceSync`/`clientWaitSync` with a timeout
  (answered `TIMEOUT_EXPIRED` until the next frame task, never a spin),
  `EXT_disjoint_timer_query` (not exposed), `getQueryParameter` of
  `TIME_ELAPSED` (not exposed).
- `getBufferSubData` (WebGL 2 readback): the same rule as `readPixels`.
- Extensions that widen the attack surface (`WEBGL_debug_renderer_info`: not exposed;
  `WEBGL_lose_context`: allowed, it only drops page objects).
- Shaders with `while`, data-dependent loop bounds, or dynamic indexing into
  arrays of samplers: refused at link (outside the subset).
