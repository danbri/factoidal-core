## What moved upstream

`third_party/testing/w3c` moved to w3c/rdf-tests ec2ba15. Two manifest
shapes changed.

1. Protocol and Graph Store Protocol tests. The old form put the request
   and response in `rdfs:comment` as Markdown ("#### Request",
   "#### Response"). The new form is structured: `mf:action` is an
   `ht:Connection`; `ht:requests` is a list of `ht:Request` (`ht:methodName`,
   `ht:absolutePath`, `ht:headers`, `ht:body` with `cnt:chars`) and each
   request has an `ht:resp` with `mf:expectedStatus` (`hts:*`),
   `mf:expectedFormat`, `mf:expectedBoolean` and `mf:expectedLocation`.
2. `graph-store-protocol/manifest.ttl` has no `mf:entries`. It uses
   `mf:include` for `manifest-direct.ttl` and `manifest-indirect.ttl`.
   `http-rdf-update` entries now carry two `rdfs:comment` literals.

The runner reads these shapes in general form. It has no per-test case.

## Trailing VALUES and query result order

SPARQL 1.1 section 18.2.4 gives the order for a query result:

1. group and aggregate (18.2.4.1) and HAVING;
2. join the trailing VALUES clause (18.2.4.2);
3. evaluate SELECT expressions (18.2.4.3);
4. ORDER BY, then project (18.2.4.4), then DISTINCT, OFFSET, LIMIT.

Grammar rule 12 gives ASK a `SolutionModifier`. CONSTRUCT (section 16.2)
slices the ordered rows.

The F* AST already had `q_values`. It joins BEFORE grouping, and SHACL
pre-binding of `$this` depends on that. A new field
`q_post_values : option (list (list (var_name * rdf_term)))` holds the
trailing clause. It joins AFTER grouping and HAVING.

Files:

- `SPARQL11.Algebra.fst`: helpers `eval_grouped_select`, `form_rows`,
  `ask_solutions`, `construct_solutions`; `eval_select_query`,
  `eval_ask_query` and `eval_construct_query` call them.
- `SPARQL11.Parser.fst`: `parse_trailing_values`, `place_trailing_values`;
  SELECT, ASK, CONSTRUCT and DESCRIBE read a trailing VALUES clause; ASK
  reads a solution modifier. Scope rules count VALUES variables. Three
  parser faults found on the way are fixed: an inverted `SI_Var` test in the
  implicit-group check, a bare `LIMIT` or `OFFSET` that was swallowed, and
  `ORDER BY` start tokens that missed built-in call keywords such as `LCASE`.
- `SPARQL11.Store.fst` and `SPARQL.Plan.Streamable.fst`: the backend and
  the streaming fast path decline a query with `q_post_values`, GROUP BY,
  HAVING or an ASK offset, so the reference evaluator answers it.
- `SPARQL11.Parser.AskBgpRoundTrip.fst` and
  `SPARQL11.EntailmentRegime.RDFS.fst`: proofs about the ASK parse shape
  changed with it. `ask_tail_clean`, `lemma_parse_solution_modifier_clean` and
  `lemma_parse_trailing_values_clean` are new. The lemmas in
  `EntailmentRegime.RDFS` gain hypotheses that the new fields are `None`.
- `OWL.QueryRewrite.fst`, `SPARQL.Diagnostics.fst`: record literals gain
  `q_post_values = None`.

Unit tests: `tests/unit/sparql_trailing_values_unit.ml`, 43 pass, 0 fail
(out of 43). It covers language-tag equality, VALUES after grouping, ASK and
CONSTRUCT modifiers, grouped ORDER BY, scope rules, the Protocol conflict,
XMLLiteral canonicalisation and D-entailment.

## Local overrides

Three Graph Store tests stay failing in the F* tree and are counted as
`local-override`: two `multipart/form-data` requests and one POST that
creates a graph and answers a `Location` header. `SPARQL.GraphStore` has no
multipart parser and no way to mint a graph IRI. The files are under
`tests/local-overrides/graph-store-protocol/`, kind `engine-gap`, and name the
placeholder issue <https://github.com/danbri/factoidal/issues/698>. If a
test starts to pass, the runner prints STALE and exits 1 until the override
file is removed.

## Exit status of `build-ocaml.sh test`

The test step runs `w3c_runner --all` and keeps its status in `W3C_RC`. The
runner exits 0 when every suite has 0 fail and no override is stale, 1 when a
test fails or an override is stale, and 2 when the harness found no manifest
or no test. The step then cuts `w3c_results.log` into `sparql_results.log` and
`rdf_results.log`, runs `generate-report.sh`, and exits with `W3C_RC` if it is
not 0, otherwise with the report status. It prints `TEST_STATUS=OK` or
`TEST_STATUS=FAIL`. Before this change the step dropped `W3C_RC`, and
`generate-report.sh` failed in a fresh checkout because the two split logs did
not exist.

## Limits that remain

- The F* Protocol suite checks decode and parse only. It does not check
  `mf:expectedBoolean` or `mf:expectedFormat`, carries no state between
  requests, and does not apply `using-*` parameters to an update. The Lean
  runner (`formal/lean4/Harness/ProtocolRun.lean`) checks
  `mf:expectedFormat` and `mf:expectedBoolean`. No issue is open yet.
- `rdf-mt` has 1 unsupported test (XMLLiteral well-formedness). It was
  unsupported before this work.
- `Parser.RDFXML` canonicalisation of XMLLiteral character escaping is not
  checked by any W3C test.
