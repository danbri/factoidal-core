## Order of work

Ranked by subtests per unit of work, with real-site value (the UK survey in `priorities.md` of the
run directory) as the tie-break.

1. **WebAssembly JS API** (189k). In progress.
2. **Small fixes with large counts**, one agent, one branch each, measured before and after:
   the `fetch` body bug (about 9k), the two crash sites (11.5k), `document.open` (11k), cross-frame
   `contentWindow` calls (23.7k), WebCrypto error order (35.5k), `elementsFromPoint` (9.9k). About 100k
   subtests together, so 4.4 points, and each is small.
3. **Merge the built branches**: `wip/bp-default`, `wip/bigdoc-perf`, `wip/form-submit`, `wip/esm-scripts`
   (one at a time through leanlock, each needing an engine build).
4. **Web Animations** (55k of CSS interpolation plus `web-animations/`), then **`execCommand`** (77k
   plus `editing/other`). Both are larger pieces of work, and both matter on real sites less than the
   storage and layout items below.
5. **Real-site items that WPT undercounts**: `document.cookie` and storage (18 of 21 UK sites), flex
   and grid layout (14 of 21).
6. Typed OM, SharedWorker, custom elements, Temporal.

Items 1 and 2 together are worth about 290k subtests, or about 13 points: from 63% to about 76% on the
headline, and from 25% to about 51% without encoding.

## How progress is measured

- A full run after each merge to main that changes the engine. It takes about 3 hours with 3–4 jobs on
  one Mac, and one run at a time: `wpt-score.py` now refuses a second run on the same ports
  (6af85600a).
- Score it with `wpt-full.py` and commit the JSON next to this one, so each step is a measured diff.
- The daily CI job's 4,000-test sample is a rough check between full runs, not a score to plan from.

## Blocker

Building needs at least 4 GiB of free disk; about 3 GiB is free. Every item above needs an engine build.
