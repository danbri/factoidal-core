## Design: a layer over the Core engine

`L4Factoidal/RIF/Bld.lean` reuses the Core engine's matcher
(`RIF.matchFormula`), built-ins (`RIF/Builtins.lean`), value identity
(`groundMatch`, `literalValue?`) and the RIF-PS reader (`RIF/Ps.lean`).
It adds what BLD has and Core has not:

| BLD feature (§) | Where | How |
|---|---|---|
| Equality in conclusions (§2.3) | `Classes`, `assertEq`, `closeEq` | Equality classes of ground terms, closed under congruence and list injectivity (§3.4, `Ilist` injective). Facts, rules and goals are read through `canon` (class representative; a data value when the class has one). |
| No model (§3.4) | `classClash`, `inconsistent` | Two different data values, a data value and a list, or two lists of different length in one class: every goal is entailed. |
| `##` and `#` (§3.4) | `bldAxioms` | `Isub` transitive; `Iisa ∘ Isub ⊆ Iisa`, as two safe Core rules. |
| Rules whose body does not bind a variable | `unboundVars`, `seeds`, `fireRule` | The variable is instantiated over a finite set of terms (the terms of the facts, rules and goal, grown by computed values). A positive answer is sound; a negative one is `undecided`. |
| Built-ins on equal terms | `expandBuiltins` | A ground built-in call in the goal holds when it holds for some members of the argument classes. |
| Named arguments (§2.1 item 5) | `Ps.lean`, `namedArgSpace` | Positional term with name-sorted arguments in a reserved symbol space (bag semantics). |
| Open lists (§2.1 item 4) | `Ps.lean`, `openListSpace` | `List(a | t)` with a closed tail folds to a closed list; otherwise a free term (`groundMatch` answers `no` against a closed list). |
| Conjunctive conclusions (§2.3) | `Ps.parseClause` | One rule per conjunct. |
| No free variables (§2.6) | `documentWellFormed` | Replaces Core safeness for the syntax test. |

The RIF-RDF combination (RIF RDF and OWL Compatibility 2013, §5.1.1,
conditions 7 and 8) is `rdfCombinationRules`: `rdf:type` and `#` agree in
both directions and `a ## b` gives `a rdfs:subClassOf b`, not the converse
(`RDF_Combination_SubClass_5`). Under an RDFS import the facts are read
through the full RDF 1.1 Semantics closure (`RDFS.fullClosure`).

Finding: the Core runner maps an imported `rdfs:subClassOf` triple to a
`##` atom (`RdfMapping.factsOfTriple`). Condition 8 has one direction
only, so that mapping is unsound; it does not change a Core verdict
because RIF Core formulas cannot write `##`. The BLD path drops it.

Finding: Core's `boundFix` reads `?N1 = External(f(?N))` as binding `?N`
from `?N1`, and counts a variable inside `External(...)` in an atom as
bound. Both are wrong for evaluation; `Bld.boundBld` binds only in the
direction of computation.

## Theorems (`RIF/BldTheorems.lean`)

- `bld2013_canon_without_equalities`: with no equalities `canon` is the
  identity on terms and term lists.
- `bld2013_assertEq_refl`: `t = t` adds no class.
- `bld2013_inconsistent_entails`: a clash of the classes entails every goal.
- `#guard`s: `bldAxioms` and `rdfCombinationRules` are safe Core 2013 rules
  and need no universe.
