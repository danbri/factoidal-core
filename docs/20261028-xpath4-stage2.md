## Theorems (`XPath4/Theorems.lean`, `XPath4/Json.lean`)

Proved, no `sorry`:

* `nodeLt_irrefl`, `nodeLt_trans`, `nodeLt_total`: document order is a strict
  total order.
* `nodeRef_at_doc`, `nodeRef_at_rt`, `nodeRef_at_idx`, `Env.doc_rt`: the axes
  stay in one tree; a runtime node reads its own tree.
* `parseXml_eq`: `fn:parse-xml` with no options builds `Doc.ofNodes` over
  `XML.Document.children` of the project's XML parser, when the parser
  accepts the text, the text is namespace-well-formed and needs no external
  resource.
* `parseJsonText_eq`: `fn:parse-json` is `JSON.parseJson` on a text with no
  unpaired surrogate escape.
* `x2jEscChar_eq_escapeChar`: `fn:xml-to-json` escapes a string character as
  `JSON.escapeChar` does, outside the characters the XPath rules treat
  specially.
* `upperCase_shared`, `lowerCase_shared`, `encodeForUri_shared`,
  `iriToUri_shared`, `escapeHtmlUri_shared`, `contains_shared`,
  `substringBefore_shared`, `substringAfter_shared`: these `fn:` functions are
  the `Fn.String` functions that SPARQL, RIF and RML call (the last three
  when the default collation is the codepoint collation).
* `matches_shared`: `fn:matches` is `Regex.isMatch`; `matchAt_eq`: the
  matching segments come from `Regex.cmatch`.

Tested (`#guard`), not proved:

* XPath 1.0 (`XPath.Full.evalText`, the XSLT 1.0 and GRDDL engine) and
  XPath4 give the same string on 46 XPath 1.0 expressions over one document
  (the 1.0 axes, predicates, core functions).
* `xml-to-json(json-to-xml($j)) = $j` on three JSON texts in normal form.

Open:

* Preorder of `Doc.ofNodes` (index order = preorder, parent links agree with
  `XML.Node` children): the builder is a `StateM` loop, the proof needs loop
  invariants.
* 1.0/4.0 agreement over the whole 1.0 fragment (needs a simulation between
  the two node models).
* The JSON round trip as a theorem.

## Dataflow registry

`Dataflow/Registry.lean` gets an entry "XPath 4.0 evaluation" with status
`tested` (the qt4tests numbers above), in a separate commit. A `proved`
entry would name declarations of `XPath4`, and the registry is imported by
the library root, so that would put `XPath4` in the library root (and in the
wasm build). The owner decides.

## Not implemented (Stage 3 and later)

JNodes (`fn:jtree`, `jnode()` tests, paths over maps and arrays),
`fn:element-to-map`, `fn:map-to-element`, `fn:serialize` (and with it the
runner's `serialization-matches`), CSV (`parse-csv`, `csv-to-xml`,
`csv-doc`), `parse-html`, `parse-uri`, `build-uri`, `build-dateTime`,
`parts-of-dateTime`, `fn:update`, `fn:hash`, `random-number-generator`,
UCA tailorings and the UCA `reorder` parameter (`XPath4/Collation.lean`
gives the DUCET root order for every `lang`), regex back-references, lookahead groups, `\P{..}` and
character class subtraction (the regex engine), non-English names in date
formats, IANA time zones in the `place` argument, `trust-external` on an
external DTD that names further resources, binary resources.
