# XSLT 4.0 Stage 1: a non-streaming XSLT 4.0 processor in Lean

Date: 28 October 2026. Issue: https://github.com/danbri/factoidal/issues/1101
(QT4); open items: https://github.com/danbri/factoidal/issues/1149. Branch
`claude/qt4-xslt`. Target release: 0.21.0.

Sources: XSLT 4.0 editor's draft at
https://qt4cg.org/specifications/xslt-40/Overview.html (read 2026-10-28);
the XPath 4.0, F&O 4.0 and Serialization 4.0 code in `main`; tests: the
non-streaming test sets of https://github.com/qt4cg/xslt40-test, commit
`91328fbf0fed4a5d2813eb3661808ee53cb961ba` (2026-10-13), vendored in
`third_party/testing/xslt40-test/` (see its `PROVENANCE.md`).

## What was built

| File | Content |
| --- | --- |
| `XSLT4/Tree.lean` | the output of a sequence constructor (`Out`), the construction of new trees (§5.7.1: content normalisation, namespace fixup), deep copies |
| `XSLT4/Ast.lean` | the compiled stylesheet: instructions, templates, functions, keys, modes, globals, attribute sets, accumulators, output definitions |
| `XSLT4/Static.lean` | static context, XPath and sequence-type parsing with `xpath-default-namespace`, value templates, patterns (XNode patterns, `~T` and `type(T)` type patterns) and their default priorities |
| `XSLT4/StdFns.lean` | `system-property`, `function-available`, `element-available`, `type-available` (also in static expressions) |
| `XSLT4/Compile.lean` | modules, `xsl:include`, `xsl:import` and import precedence, simplified stylesheets, static variables and parameters, `use-when`, shadow attributes, `fixed-namespaces`, all instructions and declarations, attribute checks (XTSE0090, XTSE0020) |
| `XSLT4/Interp.lean` | the evaluation: template rules and modes (built-in rules, conflict resolution), `apply-templates`, `call-template`, `next-match`, `apply-imports`, parameters and tunnel parameters, `for-each`, `for-each-group`, `sort`, `choose`/`if`/`switch`, `iterate`, `try`/`catch`, `merge`, `analyze-string`, `number`, `copy`/`copy-of`, node constructors, `message`, `assert`, `map`/`map-entry`/`record`/`array`/`array-member`, `evaluate`, `result-document`, `where-populated`, `on-empty`, `on-non-empty`, `perform-sort`, `source-document`, `fork` |
| `XSLT4/Transform.lean` | whitespace stripping, global variables, the host functions (stylesheet functions with optional parameters, `current`, `key`, `document`, `regex-group`, `current-group`, `current-grouping-key`, merge functions, accumulators, `copy-of`, `snapshot`), the initial invocation, serialization through `XPath4.Serialize` |
| `XSLT4/Theorems.lean` | the theorems and `#guard`s below |
| `Harness/Xslt4Run.lean` | `lake exe l4xslt4`: the xslt40-test runner, and `--xslt10 DIR` (agreement with the XSLT 1.0 engine) |

The XPath 4.0 evaluator gets one hook: `Env.host`, functions of the host
language by name and arity (`XPath4/Core.lean`, `XPath4/Eval.lean`; 28
lines). It is consulted before the built-in library for static calls,
named function references and dynamic calls of built-in function items.
It is empty for XPath, so XPath results do not change (qt4tests below).

Everything is total: the compiler and the interpreter take a fuel argument
that decreases on every nested call; exhausting it is `FOER0000`. No new
`partial def` (`tools/lean-hygiene-audit.py`: 163, the baseline). The tree
is not imported by the library root `L4Factoidal.lean`, so the wasm and the
npm package do not change.

## How a test is scored

A test case is **unsupported** when a dependency is not met: a spec
dependency without XSLT 4.0 (`XSLT10+`, `XSLT20+`, `XSLT30+`, `XSLT40+`,
`XSLT40` are met), a feature other than `higher_order_functions`,
`serialization`, `backwards_compatibility`, `dynamic_evaluation`,
`XPath_3.1`, `XSD_1.1`, `HTML5`, `built_in_derived_types`, or an
environment with a schema, collection or package. Unsupported is never a
pass. An `error` assertion passes only with the expected code. The result
is delivered as a document node (the default of the catalog's driver,
`runner/run-tests.xsl`), unless the output method is `json` or `adaptive`.
Serialization assertions use the stylesheet's output definition.
`assert-message` holds, as in the catalog's driver. `--isolate 30` runs
each test set in child processes with 30 seconds per test case; a test
that does not finish counts as a fail and the run goes on after it.

## Theorems (`XSLT4/Theorems.lean`)

Proved, no `sorry`; `#print axioms` gives `propext`, `Classical.choice`,
`Quot.sound` only:

* `parse_eq_parseXPath`: with no `xpath-default-namespace`, an XPath
  expression of a stylesheet is what `XPath4.parseXPath` reads.
* `materialize_item`: an existing item is delivered as itself.
* `patMatch_ctx`, `patMatch_type`: the pattern `.` matches every item; the
  type pattern `~T` matches exactly the items that `Env.itemMatches` gives
  for `T`.
* `stripDoc_noRules`: with no `xsl:strip-space`, whitespace stripping is
  the identity.
* `findRule_empty`: with no template rules no rule matches.
* `defaultPriority_*`: the default priorities of §6.4 for the basic forms.

Tested (`#guard`, checked by `lake build l4xslt4`): the identity transform
(template and `on-no-match="shallow-copy"`) gives a result deep-equal to
the source on four documents; serialized results parse as well-formed XML;
on three XSLT 1.0 stylesheets XSLT4 and `L4Factoidal.XSLT` give the same
text.

Open (https://github.com/danbri/factoidal/issues/1149): agreement with
`L4Factoidal.XSLT` on the XSLT 1.0 fragment, the identity transform on every
document, well-formed output of every transformation, as theorems.

## XSLT Streaming 4.0 (next)

What it needs: a streamed reading of the source (an event stream over the
XML parser instead of a node table), the streamability analysis of the
Streaming spec (posture and sweep of every construct; the catalog's
`assert-posture-and-sweep`), streamed `xsl:source-document`,
`xsl:iterate`, `xsl:fork`, `xsl:merge` and accumulators, and the `strm`
test sets (45 MB, not vendored here).
