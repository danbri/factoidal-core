# VP8 keyframe residuals for WebP

The residual reader uses the existing keyframe predictions and keeps one arithmetic cursor per coefficient partition. It folds the quantised Y2, Y, U and V blocks in macroblock raster order, allowing reconstruction to consume a record without retaining a frame-sized coefficient array. A skipped macroblock consumes no coefficient bits. Above and left occupancy remain in raster order and connect across partition boundaries.

`zigzag_injective` proves that a later scan position cannot overwrite an earlier coefficient when storing row-major transform inputs. Each block has 16 coefficients by type. Success for a coded macroblock carries an exact 24-block YUV count, with an optional Y2 block. Each block's token walk visits at most 16 positions. The first hosted pass matched every coefficient for the BBC inputs but exhausted a valid, tightly packed libvpx coefficient partition. The arithmetic reader now keeps only the high byte of its decision value and normalises before the next decision. `decision_uses_high_byte` proves that the buffered decision threshold is determined by this byte. The reader still refuses an attempt to read beyond the indexed span. These facts leave end-to-end equivalence to the VP8 specification open.

The differential probes all quantised coefficients (before any dequantisation or transform) in the 11 archived BBC VP8 photos and two four-partition libvpx images, one with skipped macroblocks. No new browser image path is enabled by this change. Reconstruction, loop filtering and presentation still follow.
