# Independent pre-Shanghai header encoding and computed parent link

Issue #852; stacked on #851 at 018b72a4978a805b80e650ff8c6a1bafbf191052. Existing EIP-1559 checks now have an adapter that reconstructs canonical RLP from the complete ordered legacy/London fields, checks integer minimality and byte widths, and calculates the actual parent digest in the existing pure Lean Keccak code before invoking HeaderChain.check. The CLI requires the existing explicit experimental Keccak opt-in. No new runtime dependency or compiler is introduced; the existing lockfile's noble Keccak is test-only. 

The supported layout is 15 fields before London and 16 from London until the Shanghai timestamp. This is a bounded encoding profile, not complete block validation or a general RLP decoder. No supplied canonical-head assertion is authenticated. PoW/PoS validity, withdrawals/requests, trie roots, full fork rules, independent RLP and Keccak refinement remain open. The transport reads a local test file before applying line caps; it is not a network admission boundary.

Reproduction from formal/lean4/evm-cleanroom: `lake -f lakefile-header-rlp.toml build evm-header-rlp`, `lake -f lakefile-header-rlp.toml env lean EVMCleanroom/HeaderRLP.lean`, then from scripts/differential `npm ci && node header-rlp.mjs "$PWD/../../.lake/build/bin/evm-header-rlp"`. The workflow emits source blob pins, actual axiom sets, native observations and controls. The test inventory is generated deterministically; no pass is claimed until CI actually runs. Local Lean and lower-cost coding worker are unavailable in this runtime; local build, benchmark and independent reviewer not claimed. Keep draft and unmerged.
