# Valid and invalid form selectors

The [full Linux WPT run](https://github.com/danbri/factoidal-builds/actions/runs/45647054675)
at `056c528ccb5844b01628e0cd667520535dee16cc` ran the validity selector fixture.
The earlier matching baseline had 3 of 30 passes.

Use the same Lean validity calculation for the exposed built-in control API and
CSS selectors. A form checks its owned controls, including associated controls
elsewhere. A fieldset checks its descendants. Reuse the candidate check and the
sanitized current value. The script realm keeps the custom error message and
mirrors its presence to the DOM so the cascade can reflect it.

Compile the raw ECMAScript `v` pattern once per check, anchor the parsed expression
at both ends, and handle each address of a multiple email field as required.
CSS and the exposed validity object both use that match.

Lean 4.33.1 elaborated the updated validity and selectors modules in a scratch
dependency overlay. Local guards exercised form ownership, fieldsets, custom
errors, disabled controls, patterns, and changed values. Browser WPT measures the
page and style integration.

[HTML validity selectors](https://html.spec.whatwg.org/multipage/semantics-other.html#selector-valid).
