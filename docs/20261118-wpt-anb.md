# An+B parsing and serialisation

Work: https://github.com/danbri/factoidal-core/pull/602 (small unfinished WPT fix
from https://github.com/danbri/factoidal-core/issues/598).

CSS Syntax 3 §6.2 requires the leading plus to touch `n`. Reject `+ n` before
removing whitespace. CSSOM reconstruction of `5n- 5` must not insert a plus
after `n-`. The original change is from branch `wip/wptbulk4-anb`.

The property `L4Factoidal.DOM.Selectors.anPlusB_plus_ws` states that a leading
plus followed by any character satisfying `isWs` is rejected for every suffix.
It does not establish the whole An+B grammar. The theorem's axiom report is
printed during the build. The compiler and runtime remain trusted.

Parser guards cover valid and invalid leading plus forms and negative offsets;
CSSOM guards cover rejection and canonical text. WPT's
`css/css-syntax/anb-parsing.html` provides independent cases. No page rendering
or script execution path changes for pages without these selectors.

`git diff --check` passed. `tools/premerge.sh --changed` passed six checks.
The initial Linux build found a failing proof simplification: unfolding `isWs`
before using its hypothesis lost the rewrite. The proof now rewrites the
hypothesis without unfolding `isWs c`. No failing proof was merged.

Local Lean checks cannot start because the shared build lock cannot inspect the
process table in this sandbox. Linux build and WPT results are recorded on the
PR. No WPT gain, timing improvement or complete conformance claim is made here.
