## Independent timer review

# Independent review of the timer partition statements

**Accept the four statements for the pure timer model.** The two membership equivalences add the missing converse to the existing `due_sorted` result. `fire_no_due` carries it through the actual transition. `fire_idempotent` protects the whole state on an immediate second fire. A claim that the first fire enqueues exactly one correct callback per timer needs a further theorem. Reviewed source at `e46300e8da8067b18eff46d39d8bf3dd74a4f0a2`. [PR 609](https://github.com/danbri/factoidal-core/pull/609) · [Item 608](https://github.com/danbri/factoidal-core/issues/608)

## Premise and reachable inputs

`Sorted` means pairwise nondecreasing keys `(due, seq)`. It neither mentions a clock nor specifies a partition. The initial empty state satisfies the stronger `Inv` by `initial_inv`, and `Input.apply_keep` preserves it through every model input. Starting at clock zero, arming timers with timeouts zero and five produces a reachable, nonempty queue whose first firing leaves both the due and retained parts observable. Two timers with equal due times exercise the sequence tie-break. These are genuine inputs, and sortedness is essential to the two completeness statements: the prefix algorithm stops at the first future timer even if an overdue timer follows in an unsorted list.

The real wire caller in `labs/demos/foafnaut/WebEventLoop.lean` decodes the timer list, checks adjacent keys and every sequence number against `nextSeq`, and refuses a failed check. I found no theorem converting successful `WebEventLoop.stateOf j = .ok st` into `Inv st`. Adjacency suffices mathematically by `keyLe_trans`. Its proof would connect the input boundary to the model. A full wire round-trip would additionally need the wire's size and numeric bounds. The generic `Driver` can receive arbitrary `loop`, `setLoop` and callback functions; a claim about every such host also needs preservation laws.

## What the four statements cover

- `mem_due_now_iff` and `mem_due_later_iff` distinguish whole timer records. Equality at the current clock is included in the first part. Their proof uses the stopped head and key ordering to rule out an overdue record anywhere in the remaining suffix. Individual membership loses multiplicity. The existing `due_parts` states the stronger list identity `now ++ later = input`. Together with the mutually exclusive due predicates, it accounts for every occurrence and its position. `Sorted` alone permits duplicate records, duplicate IDs and equal sequence numbers. It guarantees no per-ID uniqueness. Equal-key records retain their input order because the implementation takes a prefix and suffix.
- `fire_no_due` says every timer remaining after `State.fire` has deadline strictly greater than the resulting clock. `fire_parts` identifies that clock with the original one, and identifies the returned list with the due prefix. The return type is `List Timer`; the wire `advance` operation returns its length. Timer IDs reach `Run.timer` later when a task is selected.
- `fire_idempotent` states equality of the entire second state, including its queued tasks, clock, active IDs and current task, and an empty second return list. There is no intervening step or clock change. In fact it holds for arbitrary timer lists: after a prefix scan, the remainder is empty or starts with a future timer, so the same scan stops immediately. This shows why idempotence by itself cannot certify completeness. Repeating `advanceTo target` is a different operation. Two pending deadlines before one target can be visited on two successive advances.
- The new statements would still hold if the first fire omitted every task append but maintained the same retained and returned timers, or doubled the append for each nonempty due prefix. Thus they do not certify the correspondence between returned timers and tasks actually queued. Nor does a queued task establish execution: a later clear makes it unrunnable, and an interval may rearm only after callback completion. The theorems establish no time or work bound, fairness or host timing guarantee.

## Additional obligations in order

1. State the observable first-fire equation against `filter (fun t => decide (t.due ≤ st.clock)) st.timers`. The returned list equals this stable list, the residual equals its complementary filter, and the task queue equals its exact old prefix followed by one timer task per occurrence in order, with the record, handle, nesting and source copied correctly. Using independent filters and explicit task fields makes a dropped, duplicated or mislabelled task break the theorem.
2. Lift completeness to `State.advanceTo target`, with the threshold equal to the *resulting clock*. The virtual scheduler can stop at the earliest deadline before the requested target. An external claim about the reported fired count should connect it to that selected list's length.
3. Prove the JSON admission-to-`Inv` bridge for the wire caller. If broadening idempotence is useful, prove it without sortedness as a separate small law, keeping the ordering hypothesis on due completeness. A separate reachable-state invariant would be needed for any distinct-ID claim.

# Independent review of blob URL quotas

The proofs under review do not establish admission availability, exact victim selection, or an aggregate memory ceiling. [Item 610](https://github.com/danbri/factoidal-core/issues/610) · [Review PR 609](https://github.com/danbri/factoidal-core/pull/609)

## Statements and boundary cases

Let P(s) be the sum of `e.body.size` over the entire entry list, counting each occurrence. `default_payload_quota` supplies an actual base case. `add_payload_quota` takes prior `held = P(s)` and an actual successful return, and relates the old and new lists to each other. The source list, increment, resulting counter and checked upper bound are independently observable. An empty default and a fresh URL with a small body provide concrete satisfying inputs. The invariant can then be maintained through later additions and revocations. Public `Store` constructors also admit a stale or fabricated counter. Successful addition checks that counter; a bound on the true retained payload would be false in general without the accuracy premise.

The byte limit is 256 MiB and the entry limit is 4,096. The runtime accepts an addition reaching either limit exactly if the other checks pass. With 4,095 entries, it can allocate the last slot. At maximum byte count, a fresh URL for an empty body can still use an available slot. A full entry list refuses even a zero-byte body. A colliding generated URL is refused regardless of size. The collision comparison is against the entire URL string in all entries. Two distinct URLs can point to equal or physically shared bytes, and their sizes count twice. These facts about the guard follow from reading `add`. The new successful-add theorem has no conclusion for a refusal and does not promise a success.

`revoke_payload` recomputes `held` from survivors and proves P and entry count cannot increase for *any* initial counter. If an initial counter is stale low, the resulting counter can increase even with no matching entry. The monotonicity compares payload sums, never old versus new `held`. The runtime removes every entry whose URL string **and** origin match, including all matching occurrences in a malformed duplicate list. A different origin or unmatched URL preserves all entries, while still repairing the counter. Resolve drops the requested fragment; revoke compares its URL literally. No quota theorem establishes behaviour for a particular revoked owner or URL. `revoke_payload_quota` preserves the limits when the *prior actual sum and prior length* satisfy them. An already over-quota store need not become compliant after an unrelated revoke.

## Real API and claims to reject

`Net.Xhr.State.blobs` defaults to the empty store. WebApi op 90 selects the session's page origin, draws a UUID, calls `add`, and installs precisely the returned store on success. Op 91 passes that origin and a URL to `revoke`. A registry refusal at op 90 preserves the blob store; a successful random draw has already changed the generator state and draw count, so the entire WebApi state can change on that refusal. An entropy refusal is a distinct earlier result. `LeanJSWorkers.workerNet` explicitly copies the owner's blob store into the worker's initial state. The invariant transfers to that copy if the owner meets it. The bound applies to a single Store value. Metadata, copies, pre-existing Blob objects, buffers held by code outside the registry, previous states, other realms, allocator overhead and peak memory are outside P. The origin parameter controls entry access and revocation; the quota itself is global across entries of one store.

The existing success guard is one sample.

3. # Independent review of RDF collection output bounds

**Accept all three statements as bounds on the number of returned terms after a successful call.** The strict inequality is correct and tight for the callback walker. It does not establish correct decoding of a well-formed list, correctness of a dataset index, or a time, byte or memory bound. I reviewed source at `466930be071f04f4e2bdd381aed9da14bc8b312b`. ## Off-by-one and witnesses

`listWalk` checks fuel first. With zero fuel it returns an error tagged `cycle`, even for `rdf:nil`. With positive fuel and a nil head it returns exactly the initial accumulator's list, before examining `seen` or either lookup. With one distinct non-nil cell whose lookups each return one value and whose rest is nil, fuel two adds and returns one item. Fuel one consumes that first step and stops at zero. More generally, k successful continuations need k+1 fuel, including the nil step. For exactly that much fuel the output length is `acc.size + k`, witnessing the sharp strict bound. Repeated *item values* are permitted; the cycle check applies to the traversed nodes.

The induction uses growth by exactly one array slot at each continuation and the terminal accumulator size. Unrelated callbacks, arbitrary initial seen lists and nonempty accumulators are correctly quantified. Failure cases, including exhausted fuel in an acyclic chain, impose no output-size conclusion. A mutant that rejected every non-nil input would still meet these statements, so they cannot replace a positive semantic theorem about well-formed chains. The implementation and existing concrete zero- and three-item checks provide nonvacuity evidence.

`listItemsBy_length_lt` instantiates the empty accumulator and seen list. `listItems_length_le` substitutes `g.length + 1`, yielding the inclusive triple-count bound, including empty graph/nil at fuel one. The graph bound is loose because it budgets all graph triples. Nothing here proves that all available fuel was needed or that each returned term has a particular triple witness.

## Indexed caller and costs

`Wasm/Ops/Collections.lean:65` reads an open dataset handle, chooses its graph and uses two callbacks, one for rdf:first and one for rdf:rest, based on `objectsOfHandle` and `matchDataset`. It supplies `datasetQuadCount od.ds + 1`. Instantiating the general theorem on an `.ok items` result gives `items.length ≤ datasetQuadCount od.ds`, even if the index were to return wrong objects. This count is for the whole dataset; the lookups are scoped to the selected graph. The successful response maps one JSON term per item. The public IO handler, handle validation, serialisation, and any index equivalence are outside the three theorem statements. Inspecting the code justifies the instantiation; a named theorem on that actual producer is still available to add.

Two graph/index lookups can occur per continued cell. Their results and costs are unspecified by the bound. Repeated seen-list searches, term equality, existing accumulator contents, the byte sizes of terms or errors, and JSON encoding costs are also outside it. Fuel bounds recursive continuations structurally independently of whether the call succeeds, but these theorems only constrain success output length.

Additional obligations that would change what a reader can rely on:

1. For an explicitly finite chain of k fresh nodes with singleton first/rest lookups ending in nil, prove that fuel at least k+1 returns exactly the old accumulator followed by the k items in order. Include k=0 and repeated item values.
2. Instantiate the bound on the actual pure branch of the indexed handler and its JSON item-array length. Separately establish that the indexed callbacks agree with scans of the selected graph if a result-content equivalence is desired.
3. A work claim needs a counter, bounds for successful and failed walks, a lookup-cost model and a bound on term/seen operations. A smaller graph-theoretic item bound would require showing that each visited non-nil cell uses distinct first and rest triples.
