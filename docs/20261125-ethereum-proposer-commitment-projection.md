In the full operation, initiate_validator_exit precedes the slashed flag and withdrawable-epoch update; slashings accumulator, penalties and rewards also change. This slice implements only an intermediate projection of two fields from the original validator, using the mainnet slot-derived epoch and EPOCHS_PER_SLASHINGS_VECTOR = 8192. It is not a valid consensus post-state and cannot be substituted for one. Exit scheduling can alter the withdrawable epoch before this operation; this projection does not simulate that effect.

The new ProposerProjection.authenticateAndProject entry point invokes the existing AuthenticatedProposer.authenticateState with the same raw witness, header, fork context and signature inputs. Failure returns no projection. On success, projectChecked checks epoch addition against the uint64 bound, updates the flag and max withdrawability floor, hashes the new validator record, reconstructs the length-mixed registry root from the original authenticated branch, then reconstructs the partial BeaconState commitment using its original registry branch and the slot-derived layout. No expected new root is accepted from the host. The existing test CLI now has a distinct project command; its successful output is labelled partial_validator_projection.

Four new theorem statements cover overflow refusal, exact two-field record update, raw authentication error propagation and the delegation to projectChecked on actual authentication success. These are conditional linkage and admission statements, not proof of SHA-256 collision resistance, BLS normative refinement, Merkle replacement completeness, canonical state authentication or full slash_validator refinement. Kernel reports are required on a fresh build; none are claimed yet for these statements.
